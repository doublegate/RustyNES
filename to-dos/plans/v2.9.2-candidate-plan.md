# v2.9.2 "Candidate" — the full audit acted on, and the release-candidate pair

The third release of the v2.9.x line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.9.x-final-audit-and-hardware-plan.md)). The line plan gave v2.9.2
the release-candidate `.rbf` pair and the maintainer's session at the
SuperStation One. The maintainer added a fifth audit to it (2026-09-27): the
32-finding report now at
[`docs/audits/v2.9.2-full-audit-report.md`](../../docs/audits/v2.9.2-full-audit-report.md),
AI-written, covering both repositories. Its RTL findings change the design, so
they land **before** the candidate pair is cut, and the pair is what goes to the
board.

## What v2.9.1 closed and did not

v2.9.1 "Hone" fixed the A/B tool, re-measured the old rejections, adopted the
dual-cabinet serialize, moved CHR into its own SDRAM bank, and pinned both
builds at seed 2 with two byte-identical compiles each. It left the dead NMI
detector's call for v3.0.0 (ADR 0042, maintainer decision) and the two non-zero
ceilings as leads. The sibling's `tb/ORACLE_COMMIT` still names v2.9.0.

## The deliverable

1. **The full audit, triaged and acted on.** Every one of AUD-01..AUD-32 gets a
   verdict with evidence in a new ledger,
   [`docs/audits/v2.9.2-full-audit-disposition.md`](../../docs/audits/v2.9.2-full-audit-disposition.md).
   A real defect is pinned by a test that fails first, fixed with the smallest
   change, and the fix's mutation is shown caught. A refuted claim is closed with
   the evidence that refutes it. The report is kept exactly as written.
2. **The release-candidate `.rbf` pair**, cut from the final RTL: on-die and
   off-die, a seed sweep if the RTL changed, two clean compiles byte-identical
   per build, and the co-simulation ladder from a clean checkout.
3. **The board kit.** Everything Strands A-F need that this machine can
   prepare: the corpus staged per the line plan, the expected values
   (md5s, AccuracyCoin mirror goldens), `bringup-log.md` rows ready for
   artefacts.
4. **Housekeeping carried in:** the sibling's `tb/ORACLE_COMMIT` moves to the
   v2.9.1 release commit, verified with `VERIFY=1 tb/fetch-goldens.sh`.

## Triage rules for this report

The standing calibration applies: a located Rust defect is trusted once a test
fails on it; **every RTL claim and every number is re-derived** before it is
acted on. Three facts are known before triage starts:

| Finding | Known before triage |
| --- | --- |
| AUD-04 (dead NMI detector) | **Decided**: removed at v3.0.0 with ADR 0042 (maintainer, 2026-09-27). Recorded, not re-done |
| AUD-21 (arbiter lost write) | v2.8.4 changed this exact path ("the arbiter can no longer lose a write"); re-derive against the current RTL |
| AUD-17 (libretro sizing buffer) | Raised by agy on #562 and declined there as unmeasured; the audit adds the run-ahead first-frame argument, which is re-examined on its merits |

A remediation that collides with a standing rule (NEVER LAUNDER, the byte-identity
and evidence rules for performance, off-by-default features, ADR 0037) goes to
the maintainer rather than being applied.

## The gate

| Item | Measured by |
| --- | --- |
| Every AUD row has a verdict | the ledger: 32 rows, each FIXED, REFUTED, DEFERRED (with who decided) or NOT A DEFECT, each with evidence |
| Each FIXED row | a test or co-simulation gate that fails on `main` and passes on the branch, and a mutation of the fix that the test catches |
| Oracle unchanged where it should be | `--features test-roms` 0 failed; AccuracyCoin 144/144; nestest 0-diff |
| RTL | ladder on-die and off-die from a clean checkout, 0 failed; seed sweep if any RTL changed; two clean compiles byte-identical per build |
| Performance-shaped rows (AUD-05, 12, 17, 18, 19) | adopted only on `ab_check.sh`'s evidence rule or, where no bench can reach the path, only when the change is behaviour-free by construction and says so |

## Blocked on this machine, and recorded

**The board strands (A-F).** Reflashing, powering, reading a display, scoping,
photographing and listening need the maintainer at the SuperStation One. This
release delivers the candidate pair and the kit; the bring-up rows are filled
when the maintainer runs them, and whatever they find is v2.9.4+ per the line
plan. **Swift changes** (AUD-10, AUD-14) cannot be compiled here; they join the
v2.9.3 device checklist.

## Out of scope

Removing the NMI detector (v3.0.0); the S2 scheduled arbiter (after v3.0.0);
any new feature.
