# v2.9.9 — the release candidate before v3.0.0

The last release of the line to v3.0.0
([line plan](v2.9.4-to-v3.0.0-line-plan.md), v2.9.9 row). v2.9.8 carried
v3.0.0's API and format breaks forward, so the line plan's "trial the removals"
item is done. What is left is making the tree a release candidate: re-audit it,
move the sibling's oracle pin and land the RTL parity work it unlocks, close
the open accuracy tickets, chase the performance leads v2.9.8 recorded, prepare
the libretro `.info` sync, and cut the release-candidate bitstream pair. v3.0.0
then ships the notes that restate every break, the libretro submission, both
bitstreams labelled release candidate, and joint tags.

The codename is chosen at the cut; this file is renamed then, as v2.9.8's was.

## Research rule

Research continues through the whole release, not only at planning. Order:
the repo's and the sibling's documents, the vendored `nesdev_wiki/` and
`ref-docs/`, then the open Internet (NESdev wiki and forums, datasheets), then
black-box comparison against reference emulators' output. Reference-emulator
source and third-party NES HDL are never opened, and
`~/Code/Forks-Projects/ref-emulation/` is never searched. Before reading any
oracle file to inform RTL work, run `grep -n "Provenance:"` on it.
