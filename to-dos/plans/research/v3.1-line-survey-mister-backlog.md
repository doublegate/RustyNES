# RustyNES_MiSTer — the backlog after v3.0.1 (input to a v3.1 → v4.0 roadmap)

Compiled 2026-10-06. Read-only research: no file was edited, nothing was built
and Quartus was not touched. Sibling at `release/v3.0.1` (`65c5940`), oracle at
`release/v3.0.1`.

**Firewall statement.** No third-party NES HDL and no reference-emulator source
was opened. The incumbent `NES_MiSTer` was consulted only through its README's
feature list (ADR 0040: public release metadata is outside the firewall). Oracle
files that carry `// Provenance:` headers were *listed* (`grep -rln`) and not
read; they matter to planning because those regions are black boxes for HDL
work (see §2.4).

**Legend.** Size: S (one release item, < 1 week), M (a release's headline),
L (several releases). Dependency: `none` / `board` / `2nd board` /
`maintainer` / `upstream`. Bitstream: `Y` = changes the RTL, so it re-opens the
seed sweep at that release's build date and produces a new `.rbf`; `N` =
docs/tooling only. **UNVERIFIED** marks anything not confirmed at its source.

**Baseline after v3.0.1.** Six mapper families (0, 1, 2, 3, 4, 7)
(`rtl/ines_header.sv:137-140`); ladder 199/0/1 on-die, 200/0/1 off-die at
v3.0.0 (`README.md` status table); v3.0.1 adds `mapper4mmc3oddskip080` and an
RTL fix (ledger 3.49), so v3.0.1 ships a new bitstream (`to-dos/plans/v3.0.1-mortar-plan.md:32`).
Fit (on-die, latest `output_files/RustyNES.fit.summary`, 2026-10-06, possibly
mid-sweep): **22,922 / 41,910 ALMs (55%), 468 / 553 M10K (85%), 33 / 112 DSP**;
off-die: 24,570 ALMs, **84 M10K (15%)**. **No hardware has run any bitstream.**

**Ordering constraint (load-bearing):** a palette, video-timing or audio-level
correction from Strand C is an RTL change, which re-opens the seed sweep at that
day's `BUILD_DATE` (seed margin is build-date-scoped: README, the 260929 and
261003 failures). So the board session should be scheduled **before** any
feature RTL lands in the same release, and the hardware-verified bitstream is
the one compiled *after* the board's fixes.

## 7. Proposed order of work

**Phase H — the board (v3.1.0, or a MAJOR; ADR 0043 Decision 2).**
HW-0 → Strand A incl. HW-A8/A9 (device + SDRAM part, first, because a wrong
device answer is an L-sized re-target) → Strand B on-die → Strand C → Strand D →
off-die strand + HW-O6 (real SDRAM constraints) → E1/E2 → F1. Fold every fix in
(each simulation-reachable finding becomes a gate first), re-sweep seeds at the
release date, re-run the failed strand and every later one, flip the anchors
(HW-X1), split the two-board box (HW-X2). Ship the hardware-verified release.
No feature RTL in this release.

**Phase S — submission prep, in parallel with H (docs only, N).**
SUB-1, SUB-2, SUB-5, TL-5; decide SUB-9 (public repo) and the comment-density
question. Submit (SUB-6) only after Phase H's gate and F3's decision.

**Phase F1 — cheap breadth (v3.2).** Options-surface first, then mappers:
FB-16 core options (region placeholder off, +8 sprites if decided, custom palette)
at the start of the release; FB-2 SUROM; the discrete/MMC3-subset batch (206
family, 66, 11, 79, 71/232, 34, 118/119, trivial discretes); FB-10 paddle;
FB-8 Four Score; FB-6 cheats (oracle-gated rung). All Y; one seed sweep per release.

**Phase F2 — the memory platform (v3.3).** FB-20 slot arbiter (+ RTL-9), DDR3
bring-up, FB-4 save states (then FB-5 rewind). Decide the headline build (S3)
here, since everything later is off-die-heavy.

**Phase F3 — the big boards and audio (v3.4-v3.6).** MMC2/MMC4, MMC5 (needs
F2), FME-7/5B, N163, VRC2/4/6, then VRC7; FB-12 expansion audio with each; FB-9
Zapper; FB-11 Famicom peripherals.

**Phase F4 — region and media (v3.7-v3.9).** FB-7 PAL/Dendy + VMODE; FB-13
FDS; FB-14 NSF; FB-15 Vs. System; FB-17 band-limited audio / composite
simulation (informed by HW-C4).

**v4.0 — feature parity milestone** (candidate definition): save states,
cheats, PAL/Dendy, FDS + expansion audio, Zapper, Four Score, and the mapper
families covering the incumbent's licensed-library list; DE10-Nano verified
(HW-X3) if a second board exists; re-measured incumbent comparison.

Open RTL items RTL-1, RTL-5, RTL-10 are S-sized and slot into any release's
start; RTL-2/RTL-4 are investigation items; RTL-3/RTL-6 wait on the board.
Tooling TL-1 now; TL-2/TL-3 before Phase F2 (the gate count will grow fast);
TL-6 after the current sweep finishes.

## 8. Decisions the maintainer must take

1. **Version of the hardware-verified release**: v3.1.0 or a new MAJOR (ADR 0043 Decision 2; v3.x plan :7-10).
2. **Whether to buy/borrow a DE10-Nano**, or formally re-scope the two-board box (HW-X2/X3). The live MiSTer page does not require one.
3. **Submit to MiSTer-devel at all** (F3), after F1's same-build incumbent measurement — and whether the 2026-09-26 page change (no "preservation value"/duplicate language found) alters the framing in `submission-case.md`.
4. **Make the sibling repository public** (prerequisite to any submission or fallback home).
5. **Repository transfer** to MiSTer-devel if accepted and still part of the process (one-way).
6. **Comment density** vs MiSTer's "avoid excessive documentation" principle: keep the essay comments, move them to `docs/`, or accept the review risk.
7. **Re-open the mapper scope**: TASKS.md:366 records "the remaining families" as *out of the approved scope*, a decision rather than a backlog item. Approve a new scope (e.g. the next ~10 in §2.4) and the order.
8. **Which build is the headline** (S3): on-die (runs on a bare DE10-Nano, 85% M10K, refuses 141 DB titles) vs off-die (needs SDRAM; required for most growth). And whether upstream `releases/` ever carries the off-die build.
9. **Feature priority** among save states, PAL/Dendy, FDS, cheats, peripherals, expansion audio (the incumbent has all).
10. **Hardware-dependent RTL policy**: if the board contradicts the oracle (palette, video timing, RTL-3 OAM corruption, RTL-6 APU phase), which wins, and does the oracle change too (ADR 0037 escalation, possibly a new ADR).
11. **Escalation for Provenance-headered families** (N163, FME-7/5B, VRC7/OPLL, Bandai FCG, FDS, Vs.): doc-only RTL with black-box comparison is the default; rung 4 (reading the derived oracle region) requires an ADR 0037 amendment naming the authoriser.
12. **CI investment**: a self-hosted runner or cached goldens for the full ladder (TL-3), and a containerised Quartus (TL-2).
13. **`hps_io` verification strategy** for HPS-facing features (TL-8): protocol model vs real `hps_io` under Verilator with suppressed lint.
14. **Fallback homes** (SUB-10): pursue openFPGA / Analogue Pocket or SS1 distribution regardless of MiSTer's answer?
