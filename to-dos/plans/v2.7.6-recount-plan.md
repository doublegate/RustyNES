# v2.7.6 "Recount" — the v2.7.5 deletions measured one at a time

An unplanned measurement release, cut between the v2.7.x and v2.8.x lines of
[ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md) at the
maintainer's request (2026-09-24). v2.8.0's work in progress was parked on its
own branch while this ran. Oracle only; the MiSTer sibling does not change.

## Why

v2.7.5 measured seven of the core audit's proposals in one combined ceiling
probe. That bounds their sum, not each one: a gain in one item could hide behind
another's code-layout loss, and a benchmark can fail to reach the code at all,
which is how IMP-07 sat inside the combined zero until review found it. Six of
the seven had no individual measurement: §3.1 A, B and C, the IMP-06 stores,
§3.5b and §3.6.

## The deliverable

| Item | Plan |
| --- | --- |
| The six deletions | Each applied alone, two `ab_check.sh` runs with the A/B/A control, and a 180-frame framebuffer + audio hash on both bench ROMs and both dot paths |
| Any that shows a reproduced gain | Build the correct version and A/B it |
| Zero, but a better way to write the code | Adopt on clarity alone, byte-identical, with no performance claim |
| Anything that is dead work | Record it; removal waits for the v2.9.0 deprecation decision (maintainer, 2026-09-24) |

## The gate

- Every probe hashed byte-identical, or labelled as altering the workload.
- A verdict per item from two independent runs, each read against its own
  control, recorded in `docs/performance.md` §v2.7.6 and the core ledger.
- Any code change: `fast_dotloop_diff` in a debug build, AccuracyCoin 144/144,
  nestest, the full `--features test-roms` suite, and a mutation that reverts it
  and turns a test red.

## Outcome

All six are zero individually and byte-identical. Three IMP-06 stores re-wrote
fields the fast-path guard already requires; they became a `debug_assert!`,
pinned by `fast_render_path_asserts_its_rendering_history` because no ROM in
the corpus reaches the violating state (mutating the guard left
`fast_dotloop_diff` green). §3.1 C's per-dot edge sampling feeds only the
deprecated `poll_nmi`, and §3.1 B checks an accumulator only a unit-test path
feeds: both are held for v2.9.0. Also released here: #554, the contributed
libretro buildbot fixes and targets, which were already under `[Unreleased]`.
