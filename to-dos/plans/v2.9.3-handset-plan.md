# v2.9.3 "Handset" — the mobile device checklist, and what can be proven before it

The fourth release of the v2.9.x line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.9.x-final-audit-and-hardware-plan.md)). The line plan gives v2.9.3
one subject: **the mobile device checklist**
([`docs/mobile-v2.7.4-device-checklist.md`](../../docs/mobile-v2.7.4-device-checklist.md)),
run by the maintainer on real Android and iOS devices, because every Swift change
since v2.7.4 and several Android paths have never run on hardware. This side
prepares the builds, runs everything a machine without those devices can run,
and fixes what comes back.

## What v2.9.2 closed and did not

v2.9.2 "Candidate" acted on the fifth audit and cut the release-candidate `.rbf`
pair. It added mobile changes of its own (AUD-09 to AUD-14 and their review
fixes) to the checklist as rows A13-A15 and I16-I19, two of them marked
CHANGED, UNVERIFIED in the ledger because they are Swift. It also changed the
oracle's internal-data-bus latch on an unmapped cartridge read (AUD-03), and the
sibling's `tb/ORACLE_COMMIT` still names v2.9.1, so the co-simulation has not
yet been compared with that change.

## The deliverable

1. **The checklist, ready to run.** One consolidated v2.9.3 run sheet: every row
   from v2.7.4 and v2.9.2, the build steps, and a record table per device. The
   Android debug APK is built here and its checksum recorded, so the maintainer
   installs a known build.
2. **The Android rows an emulator can reach, run on the emulator first**
   (`Pixel_8_API_34`), each recorded as EMULATOR, never as a device result. A
   failure found there is fixed before the device run, which then spends its
   time on what only a device can show.
3. **The Android JVM unit tests in CI.** `.github/workflows/android.yml` builds
   release bundles but never runs `:app:testFossDebugUnitTest`, so the Kotlin
   tests (`SocdTest`, `PersistenceTest`) have only ever run by hand. A mobile
   release is the right place to close that.
4. **The open dependency updates, consolidated.** Five Dependabot PRs (#564,
   #566-#569) touch the Android build (Gradle wrapper, androidx core), the
   workspace and CI. They are taken together on this branch so the device run
   tests the build that ships, then the PRs are closed as superseded.
5. **The sibling's oracle pin moves to v2.9.2**, with `VERIFY=1` regeneration.
   AUD-03 changed oracle behaviour, so any golden that moves is explained and the
   affected co-simulation gates re-run, rather than assumed unchanged.

## The gate

| Item | Measured by |
| --- | --- |
| Checklist rows | each row PASS / FAIL / NOT RUN with a note, per device, recorded in the run sheet by the maintainer; a FAIL is fixed (red-first where a host test can reach it) or recorded as a known issue |
| Emulator pre-run | each reachable Android row recorded as EMULATOR PASS / FAIL with how it was observed |
| CI | the Android workflow runs `:app:testFossDebugUnitTest`, and a deliberately failing test turns it red |
| Dependencies | `--features test-roms` 0 failed; AccuracyCoin 144/144; nestest 0-diff; the Android build and unit tests pass on the new Gradle and androidx |
| Sibling pin | `VERIFY=1 tb/fetch-goldens.sh` at the new pin; every changed artifact explained; the ladder's affected gates green |

## Blocked on this machine, and recorded

**The device runs themselves.** Installing on a phone, background/foreground,
audio focus, ProMotion pacing, iCloud, Files-app hand-off and thermal throttling
need the maintainer's devices. **Every Swift change is uncompiled here** (no
Swift toolchain on Linux): row B1 is its first compile. The release waits for
the maintainer's run sheet.

## Out of scope

The SuperStation One board session (it runs v2.9.2's bitstreams on its own
schedule); a mobile opt-out switch for opposing-direction cancel (the
maintainer kept it on by default at v2.9.2; desktop has the switch); any new
feature.
