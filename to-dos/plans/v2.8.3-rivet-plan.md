# v2.8.3 "Rivet" — the MiSTer core's reset, area and comments, measured

The fourth release of the v2.8.x line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.8.x-libretro-rtl-audit-plan.md)). It works from
[`rtl-audit-report.md`](../../docs/audits/rtl-audit-report.md) §4.1 and §4.3
to §5.4, and the [RTL ledger](../../docs/audits/rtl-disposition.md) rows
targeted at v2.8.3. The work is in the sibling; this repository carries the
plan, the ledger and the release.

## What v2.8.2 closed and did not

v2.8.2 "Solder" closed the correctness rows (§3.1 to §3.5). Eight rows are
targeted here: R-4.1, R-4.3, R-4.4, R-4.5, R-5.1, R-5.3 (its comment half)
and R-5.4, plus the `rtl/sdram.sv:9` citation the line plan names.

## The deliverable

1. **R-5.1:** a `reset_sync` module (asynchronous assert, two-flop
   synchronous release, marked as a synchroniser for Quartus), one instance
   per clock and reset source: `clk_sys` for the console reset and for
   `save_ctl`'s `pll_locked`, `clk_sdram` for `pll_locked`.
2. **R-4.3 / R-4.4:** each rewritten only if it is proven equivalent and the
   fit report shows it saves area. Otherwise recorded as rejected, with the
   measurement.
3. **R-5.3 / R-5.4 / `sdram.sv:9`:** the comment, format and guard fixes.

## The gate

- **R-5.1, simulation:** a `reset-sync-gate` module test that checks the
  release contract: assertion immediate, release only on a rising edge, and
  exactly two edges after the source releases. It must FAIL when pointed at
  the pre-fix wiring (a pass-through), and a one-stage mutant must fail it. A
  zero-delay simulation cannot show fabric skew, and the gate says so.
- **R-5.1, static:** the compile's STA gains a recovery / removal entry for
  `clk_sdram`, and every synchronised reset release is timed, with positive
  slack.
- **R-4.3 / R-4.4:** exhaustive equivalence (all 256 opcodes; `rmw_addr` over
  every `adl` x `index`, with `adh` covering the page wrap), plus the ALM
  count from `RustyNES.fit.summary` before and after each change on its own.
- **Whole release:** the ladder green from a frozen copy with its `TOTAL:`
  recorded; `make -C tb lint` clean; a Quartus compile at seed 4 that closes
  timing (`scripts/check_timing.py`).

## Risks

- `emu.sv` is not in the testbench file list, so the ladder cannot see the
  reset change: the unit gate and STA are the evidence, and the release says
  so.
- Delaying reset release by two clocks changes nothing the ladder compares
  (the core starts from reset either way), but the bring-up log should note
  it for v2.9.2.

## Out of scope

- The runtime `%` bank dividers (R-4.2): deliberate, documented, timing-closed.
- The off-die SDRAM build and its constraints (R-4.6, R-5.2): v2.8.4.
- Anything on hardware: v2.9.2. **No hardware has run any bitstream.**
