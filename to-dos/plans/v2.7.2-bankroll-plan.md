# v2.7.2 "Bankroll" — every bank the cartridge has, and nothing it has not

The third release of the ADR 0041 audit line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.7.x-core-frontend-audit-plan.md)). It works from
[`core-audit-report.md`](../../docs/audits/core-audit-report.md) §4.5 and
§5.2-§5.6, and the [core ledger](../../docs/audits/core-disposition.md). Oracle
only; the MiSTer sibling does not change.

Three large boards address memory the emulator cannot reach (MMC1's upper
256 KiB and banked WRAM, MMC5's WRAM banks, Namco 163's nametable and CHR-RAM
pages). Several small boards invent a `$00` where the real bus floats, and a set
of fixed-mirroring boards refuses the per-game header correction that the
fixed-mirroring gate exists to allow.

## What v2.7.1 closed and did not

v2.7.1 made six boards expose their battery RAM through `sram()`, and made every
frontend user-file write atomic. Its mapper sweep
(`battery_sram_exposed.rs`) reaches writable RAM on only 43 of 296 images; the
rest have no RAM or gate it behind a board-specific enable. v2.7.1 noted that
board-specific tests for the gated boards "belong with v2.7.2's mapper-RAM
work". They are part of this release where they touch a board changed here.

It also found that the desktop frontend persists no battery RAM at all (FE-01);
that is v2.7.3's, not this release's.

## The deliverable

Every item is pinned by a test that fails on `main` first, written from the
vendored nesdev wiki (`nesdev_wiki/`), never from another emulator's source.

| Item | Ledger | Source of truth | What changes |
| --- | --- | --- | --- |
| MMC1 SUROM / SOROM / SXROM | §5.4 | `nesdev_wiki/MMC1.xhtml` §"SOROM, SUROM and SXROM" | On boards with at most 8 KiB of CHR, the CHR bank register's bit 4 selects the 256 KiB PRG half, covering the "fixed" bank too. Bits 3-2 select the 8 KiB PRG-RAM bank: SOROM (16 KiB) uses bit 3, SXROM (32 KiB) bit 3 = A14 and bit 2 = A13. In 4 KiB CHR mode, the register that drives these bits is the one the last CHR fetch selected (PPU A12), as the wiki warns ("bankswitched as the PPU renders") |
| MMC5 PRG-RAM banks | §5.3 | `nesdev_wiki/MMC5.xhtml` §"PRG-RAM configurations" | `$5113` and the RAM-mode `$5114-$5116` values select a chip and page by the wiki's table: 0 / 8 / 16 (2x8) / 32 / 64 (2x32) KiB, with open bus where no chip is selected. `sram()` covers only the battery-backed chip, so a 16 KiB board saves only its first 8 KiB, per the wiki |
| Namco 163 nametables and CIRAM-as-CHR | IMP-11, §5.2 | `nesdev_wiki/INES_Mapper_019.xhtml` §"CHR and NT Select" | `$C000-$DFFF` select each nametable quadrant: `< $E0` is a 1 KiB CHR-ROM page (read-only), `>= $E0` is CIRAM page A (even) or B (odd). `$8000-$BFFF` values `>= $E0` map CIRAM as CHR-RAM unless `$E800` bit 6 (low half) or bit 7 (high half) disables it; those bits are currently masked off |
| `$6000-$7FFF` open bus | §5.5 | `nesdev_wiki/Open_bus_behavior.xhtml` | Boards with no RAM there, or with RAM disabled, report the window unmapped through the existing `cpu_read_unmapped` hook, so the bus keeps its open-bus latch instead of reading `$00`. Each board is checked against its wiki page before it changes |
| Hardwired mirroring | §5.6 | each board's wiki page | `has_hardwired_mirroring() -> true` only on boards whose page shows solder-pad or fixed mirroring and no mirroring register. Every candidate the audit lists is verified; one with a mirroring register stays `false`, because forcing a static layout onto such a board corrupts it (`mapper.rs` docs, the game-DB hazard) |
| Sachen `$4101` and CPU open-bus decay | §4.5 | the board's wiki page; `Open_bus_behavior.xhtml` | Triage first. The Sachen latch mixes open-bus high bits with its 3-bit register, which `Mapper::cpu_read` cannot see today. Fix only with a citation. CPU open-bus **decay** is fixed only if the wiki documents a measurable CPU-side decay; otherwise it is recorded as NOT A DEFECT, with the evidence |

## The gate

- Every item above has a unit test that **fails on `main` and passes after**,
  with the red run recorded.
- **holy_mapperel, extended.** Its SxROM driver tests SUROM's second 256 KiB
  half (the `SU` error code) and WRAM banking. New ROMs are built from the
  zlib-licensed source, as the existing 17 were, for at least an MMC1 512 KiB
  image, and SXROM's 32 KiB WRAM if the source generates it. Each must render
  **`PASS 0000`** (checked on a rendered screen, not assumed). Each is added to
  the pinned sentinel with its expected label. The 17 existing ROMs keep their
  snapshots byte-identical.
- **AccuracyCoin 144/144** (RAM decoder) and **nestest** re-measured on the
  release tree, because §5.5 changes what the CPU reads at `$6000-$7FFF`.
- `cargo test --workspace --features test-roms`: 0 failed.
- The v2.7.1 battery sweep keeps `CHECKED_FLOOR`, and gains board-specific
  battery tests for MMC5 (behind its protect registers) and for MMC1 SOROM /
  SXROM (banked WRAM exposed whole through `sram()`).
- Each fix's mutation (revert the fix) is caught.

## Risks

- **MMC1 detection by size.** Which of SNROM / SOROM / SUROM / SXROM a cart is
  comes from PRG-ROM, CHR and PRG-RAM sizes. An iNES 1.0 header carries no
  PRG-RAM size, so a 512 KiB cart without NES 2.0 is SUROM with 8 KiB. SZROM
  (64 KiB CHR-ROM + 16 KiB WRAM through bit 4) is recorded as out of scope, not
  guessed at.
- **Open bus is observable.** AccuracyCoin reads open bus. A board wrongly
  reported unmapped would read garbage where a game expects RAM, so each §5.5
  change needs the board's page, and the battery sweep still runs after it.
- **Save-state layout.** Adding latched state (MMC1's last CHR A12, N163's
  `$E800` bits) changes a mapper blob. Each is appended in a versioned way, the
  same as earlier mapper tails, with old blobs still loading.

## Out of scope for v2.7.2

- FE-01 desktop battery saves (v2.7.3).
- SZROM, and MMC5's hypothetical 128 KiB single-SRAM wiring the wiki describes
  as theoretical.
- Namco 163's `$F800` PRG-RAM write-protect nibble. The current code documents
  it as unused by the commercial library; reopened only with a game that needs
  it.
