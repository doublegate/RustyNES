# v2.7.x — the core and frontend audits, closed one finding at a time

The first of three minor lines between v2.6.23 "Pulse" and the SuperStation One
core at **v3.0.0** ([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md)).
It acts on two of the four audit reports in
[`docs/audits/`](../../docs/audits/README.md): the **core** audit and the
**frontend** audit. Both are oracle-only; nothing in this line changes the
bitstream.

**Scope in one sentence:** make the emulator safe against every untrusted input
it accepts, stop it losing save data, close the mapper gaps the audit located,
harden the desktop, web and mobile hosts, and then — last, and only where it
measures — make it faster.

## How every finding is handled

The audits are AI-written. Their calibration found the core and frontend reports
accurate at the cited lines far more often than not, and still wrong on some
numbers, on impact, and in several recommended fixes. So nothing in this line is
applied as written:

1. **Triage** it into the ledger ([`core`](../../docs/audits/core-disposition.md),
   [`frontend`](../../docs/audits/frontend-disposition.md)) with evidence.
2. **Pin** a test that fails on `main` and show it failing.
3. **Fix** with the smallest correct change, updating the subsystem doc in the
   same PR.
4. **Gate:** fmt; clippy for every feature combination including
   `retroachievements`; wasm clippy both ways; `cargo doc` with `-D warnings`;
   `cargo test --workspace --features test-roms`; the `no_std` cross-build; and
   **AccuracyCoin 144/144 and nestest 0-diff re-run**, never assumed. A change that
   touches the core or a snapshot format shows byte-identity on the existing
   goldens.

A fix that collides with a standing rule goes to the maintainer instead of being
applied. For this line that means NEVER LAUNDER, the performance bar, and
off-by-default features.

## Things known before starting

- **The performance items have prior evidence against them.** `docs/performance.md`
  already measured `#[inline]` on the hot bus functions as a **+0.60% regression**,
  and puts all of `status.rs` at **0.7%** of the profile, which caps what
  branchless flags can win. That is why they are last and why each needs its own
  A/B. Recording one as rejected is a result, not a failure.
- **The three provenance files quote Mesen2 source expressions.** That makes them
  derivation statements, whatever the audit calls them. The fix adds attribution;
  it removes nothing.
- **The pulse-1 finding is a suspicion, not a result.** It came from reading
  `rustynes-apu/src/pulse.rs:160-174` against the vendored wiki. The sibling's RTL
  follows the wiki, so if the oracle is wrong the co-simulation ladder has a blind
  spot here too; v2.8.2 adds the gate that closes it.
- **Mobile needs the maintainer.** CI compiles Kotlin, and an Android emulator runs
  here; runtime behaviour on real devices and anything Swift does not run here. The
  maintainer runs a per-platform device checklist before the v2.7.4 PR merges, and
  anything left unverified is labelled so in its release notes.

## Out of scope for this line

The libretro and RTL audits (v2.8.x); anything that changes the bitstream; the
features deferred past v3.0.0 (FDS on the FPGA, expansion audio, save states,
cheats, PAL, the other mapper families, the DE10-Nano second board).
