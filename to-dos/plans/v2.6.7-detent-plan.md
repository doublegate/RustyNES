# v2.6.7 "Detent" — the bitstream becomes a release artifact, and one cycle gets pinned

A detent is the notch that holds a mechanism at an exact position and makes that
position repeatable. Both halves of this release are that: a bitstream that is
published rather than rebuilt from memory, and an assertion pinned to the exact
cycle it happens on.

## What v2.6.6 closed, and what it did not

**Closed:** the console became a MiSTer core. `sys/` vendored byte-identical
(57 files, 0 differences), a top level, clock, palette, video sync and audio
mixer, compiled by Quartus 17.0.2 to a Cyclone V bitstream with 0 errors and
timing closed — **as shipped by v2.6.7, worst setup +0.130 ns (Slow -40C) and
worst hold +0.102 ns (Fast -40C) at seed 4**, reached by moving the work RAM
into block memory, which took the core from 30,265 ALMs (72%) to 21,865 (52%)
and bought 0.595 ns of the 0.769 ns needed -- v2.6.7 also withdraws the +0.363/+0.245 v2.6.6 published, which a clean rebuild of that configuration reproduces at no corner, TNS 0.000 on every
clock, seed pinned. Co-simulation 87 passed / 0 failed.

**Not closed, and carried here:**

- **C1** — the `$2006` v-copy delay depth is under-determined: 1-4 dots all close
  `Hybrid Addresses`, 8 and 12 fail.
- **C2** — the rung-5 gate compares verdicts, so it is blind to compensating
  errors. v2.6.6 built the instrument (`--ckpt-out`, `tb/ckpt_diff.py`) and it
  immediately found four of nine `Observable` fields written as constant `false`.
  Three were fixed; a residual remained.
- **The `.rbf` was produced and not published.** v2.6.6 deliberately left
  `releases/` empty because no hardware had run the bitstream.

## The scope, and why it is not the ladder's v2.6.7

The forward ladder puts **hardware bring-up** at v2.6.7. That is blocked and the
blocker was **confirmed by checking, not assumed**: no USB-Blaster on the USB
bus, no serial device, no block device beyond the system disk, no MiSTer mount.
No DE10-Nano and no SuperStation One are attached to this machine.

Rung 6 therefore does not close here. It moves to the first release after a board
exists. Recorded in the CHANGELOG entry and the PR body as well as here, so a
deferral cannot quietly become an omission.

What IS achievable is both halves below.

### Workstream A — publish the bitstream (maintainer directive)

The bitstream can be **built** without hardware; only *booting* it needs a board.
So it is built, named to the MiSTer convention, and attached to the GitHub
release in **both** repositories — and that becomes standing for every release
forward.

This supersedes v2.6.6's decision to leave `releases/` empty. That decision was
about not handing a user something to flash that had never run; the answer to
that is a **labelled** artifact, not an absent one.

One target, not two. Retro Remake's SuperStation One is a Cyclone V console that
forks `Distribution_MiSTer` and hosts MiSTer cores directly, so the same `.rbf`
is what it consumes. Whether the *identical file* boots both boards is the
hardware claim, and it stays deferred and labelled as such.

**It is committed to `releases/`, not only attached to the release.** The two are
not interchangeable: the MiSTer distribution mechanism reads
`releases/RustyNES_MiSTer-vX.Y.Z.rbf` out of the *repository*, so a core whose only
copy is a GitHub release asset is not distributable by the route its users
actually use. `.gitignore` therefore keeps `*.rbf` ignored everywhere except that
one path — Quartus scatters bitstreams through the build tree, and exactly one of
them is the published artifact.

### Workstream B — pin the APU frame-IRQ cycle (C2's residual)

Measured across every golden carrying a checkpoint stream: **30 of 33 comparisons
fail, and every one of them at the SAME checkpoint 7, window (28679, 32775]**.
The three that pass are runs too short to reach it. This is not a scatter; it is
one cause — the first frame-counter IRQ, at cycle 29,827.

Two candidates, both live:

1. a **trace observation point** — where the harness reads the DUT's APU relative
   to where the oracle reads its own;
2. a **real one-cycle assertion difference** in the DUT.

blargg's 2005 APU battery passes 11/11 on this DUT, which bounds the error
without settling it: those ROMs measure when the CPU *takes* the interrupt, and
interrupt latency can absorb a one-cycle difference in when the LINE asserts.

## The gate

Every clause measurable, and none satisfiable by a vacuous result:

| # | criterion | how it is measured |
|---|---|---|
| 1 | the bitstream is reproducible | `quartus_sh --flow compile RustyNES` from a clean tree at the release commit, seed pinned, exits 0 with timing closed; slack recorded as a NUMBER. **RESULT: a clean and an incremental compile give a byte-identical `.rbf`. Seed 4, worst setup +0.130 ns, worst hold +0.102 ns, TNS 0.000 on every row, 0 errors, and `quartus_clean.py` PASSES over a non-zero scan -- no Warning or Error cites `rtl/` or `tb/`.** Reaching it needed a finding the plan did not anticipate: the work RAM was 28% of the design |
| 2 | the artifact is named and published | `RustyNES_MiSTer-vX.Y.Z.rbf` attached to the GitHub release in **both** repos |
| 3 | publication is repeatable, not a one-off | a script produces and attaches it, and the release ceremony documents the step |
| 4 | **the APU residual is ATTRIBUTED** | either `tb/ckpt_diff.py` passes on every golden that reaches cycle 29,827, or the residual is shown by measurement to be a DUT assertion difference and fixed in RTL. **RESULT: the second branch, and then the first.** The residual was attributed to the DUT and then FIXED -- the `$4017` inhibit now clears the interrupt at write+3, the documented cycle. Checkpoint streams 11 identical -> **52 of 58** |
| 5 | the checkpoint gate is registered | `ckpt_diff` runs in `regress.sh` and is demonstrated to fail by mutation. **RESULT: 51 comparisons** -- 35 explicit plus the 16 instruction ROMs riding the bus gate's own DUT run at no extra cost. `put_cycle` polarity CAUGHT; `nmi_line` NOT CAUGHT and classified as stimulus-blind, with the reason recorded |
| 6 | **no co-simulation regression** | `./tb/regress.sh` no worse than v2.6.6's 87 passed / 0 failed. **Measured: 123 passed, 0 failed, 0 SKIPPED** -- from 87, carrying 51 checkpoint comparisons where v2.6.6 had none, and the first run in this project's history with nothing skipped. Two DIFFERENT AccuracyCoin numbers exist and are not interchangeable: the **oracle's own** battery is 141/141 assigned tests over a 146-entry catalog (RAM decoder), and the **DUT-vs-oracle status vector** is 146 of 146 entries identical. Both hold |

Clause 4 is deliberately an OR. "Fix it" is not a gate when which side is wrong
is unknown; "attribute it with evidence" is, and it is the honest bar.

**In the event both branches were taken, in that order, and the ordering is the
finding.** The residual was attributed first -- one cycle, on the exported /IRQ
line, with the fix hypothesis *refuted* by blargg dropping 11/11 to 4 of 11.
That refutation is what identified the fix: it proved the SEQUENCER's maturation
was correctly placed, which left only the other effects the same write schedules.
Separating the interrupt clear alone lands it at write+3, the documented cycle.
Attribution was not a consolation prize here; it was the step that made the fix
findable.

## Risks

1. **Clause 4 resolves to a real RTL defect.** Then it is a rung-4 accuracy fix
   inside a release whose other half is packaging, and the APU battery must be
   re-run to show it did not trade one error for another.
2. **The one-cycle difference is load-bearing for a second error.** This project
   has found two errors cancelling three times (`PPU_LEAD`, the v2.6.0
   observation point, the `$4017` reset delay). A fix that greens the gate is not
   evidence the fix is right.
3. **The published `.rbf` is mistaken for a verified one.** Mitigated by labelling
   it in the release body and the asset's own documentation, not by withholding it.

## Explicitly out of scope

- **Hardware bring-up** — no board. Rung 6 stays open.
- **The SDRAM controller** — its acceptance is read/write timing against a real
  part, so writing it now would be unverifiable by construction.
- **C1** (v-copy depth) — needs a stimulus sensitive to the exact dot; its own work.
- **C3** — two sub-tests the oracle itself fails.
