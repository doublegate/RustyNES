# v2.7.4 "Pocket" — the mobile apps survive what a phone does to them

The fifth release of the ADR 0041 audit line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.7.x-core-frontend-audit-plan.md)). It works from
[`frontend-audit-report.md`](../../docs/audits/frontend-audit-report.md) §2.1-§2.5,
§4 and §5, and the [frontend ledger](../../docs/audits/frontend-disposition.md)
rows AND-01..10, IOS-01..11 and MOB-01..09. Oracle only; the MiSTer sibling does
not change.

## What v2.7.3 closed and did not

v2.7.3 fixed the desktop and web frontends, including desktop battery saves
(FE-01). The mobile half of FE-01 -- no battery-save API in the bridge, no `.sav`
on either phone -- stayed here as MOB-05 / AND-09, with the rest of the mobile
findings.

## The deliverable

The maintainer's decision (2026-09-22): mobile findings are done in all tiers --
the shared Rust bridge first, then Kotlin, then Swift. What CI and an Android
emulator can reach is verified here; **the maintainer runs a per-platform device
checklist before the PR merges**, and anything left unverified is labelled so in
the release notes.

| Tier | Items | Gate |
| --- | --- | --- |
| Rust bridge (`rustynes-mobile`, `-android`, `-ios`) | MOB-01..09, FE-03 (report §2.1, not in the §8 table) | A red-first unit test for each observable fix, its mutation caught |
| Android (Kotlin) | AND-01..10 | JVM tests where the logic is pure; Gradle compile of both flavours; an emulator run for the persistence path |
| iOS (Swift) | IOS-01..11, and the Swift halves of MOB-05 / MOB-09 | Host-testable Rust tested on Linux; Swift labelled unverified, for the device checklist |

## The gate

- Every fix a test can observe is pinned by a test that fails first, and its
  mutation is caught; every non-caught mutation is classified at the site.
- `cargo test --workspace --features test-roms`: 0 failed. AccuracyCoin 144/144
  and nestest re-run, because MOB-08 is a core change.
- clippy for every feature combo, both wasm32, `cargo doc -D warnings`, fmt,
  `no_std`; `./gradlew :app:testFossDebugUnitTest :app:compilePlayDebugKotlin`.

## Risks

- **Swift does not compile on this machine**, and no pull-request job builds
  iOS. Mitigation: host-testable pieces move into Rust; the rest is kept small
  and conventional, and listed for the device checklist.
- **The panic profile.** Containing panics needs an unwinding build, which costs
  native size.
- **Two platform UIs with no UI tests.** Lifecycle, audio focus and recomposition
  can only be checked on a device.

## Out of scope

Performance and API hygiene (v2.7.5), including MOB-06, the per-frame
framebuffer copy through UniFFI.
