# v2.9.4 → v3.0.0 — finish the line, then the API major with a release-candidate core

The line after v2.9.3 "Handset", written 2026-09-29 and decided in
[ADR 0043](../../docs/adr/0043-v3-is-the-api-major-and-a-release-candidate-core.md).
It replaces the v3.0.0 of [ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md)
("the hardware-verified FPGA core") with **the API major plus a
release-candidate core**, and moves all hardware work to a later v3.x.

**Maintainer decisions behind it (2026-09-29):** v3.0.0 carries
[ADR 0042](../../docs/adr/0042-v3-removes-the-v2-7-5-deprecations-and-the-dead-nmi-edge-detector.md)'s
break and ships both bitstreams, swept and labelled not hardware-verified.
The line finishes the open backlog first and then adds targeted features, each
off by default. The only external work before v3.0.0 is the libretro `.info`
upstream sync.

It was built from three read-only surveys of both repositories on 2026-09-29
(about 230 open items). Everything below can be done without a board or a phone
unless it is listed under "After v3.0.0". Each release gets its own
`vX.Y.Z-<codename>-plan.md` when it starts, and this file stays the line's
index.

## Rules every release follows (unchanged from the v2.7-v2.9 lines)

- **Triage → pin red → fix → gate**, run through the `next-version` skill. A
  fix counts only if a test failed first and reverting the fix is caught.
- **Provenance firewall.** Reference emulators and NES HDL are black boxes.
  Before reading oracle source for RTL work, run `grep -n "Provenance:"` on the
  file. Work up the ladder in order: docs, then the Internet, then black-box
  comparison, and derived source only as a last resort.
- **New features are off by default.** Default builds stay byte-identical, and
  AccuracyCoin 144/144 and nestest 0-diff are re-run every release.
- **Any release that rebuilds a bitstream sweeps seeds at its own build date,
  for both builds** (the sibling's `docs/bitstream-release.md`: the build date is a design constant). Seed 2
  failed on-die on 260929. A release with unchanged RTL may ship the previous
  timing-clean pair byte for byte, and must say so.
- **Never claim hardware.** The "no hardware has run any bitstream" statements
  stay unchanged through v3.0.0.
- **Gates.** fmt; clippy for every feature combination (including
  `retroachievements` and both wasm builds); rustdoc `-D warnings`; the no_std
  build; the full `--features test-roms` suite; the six release audits. For the
  sibling: the `tb/regress.sh` TOTAL from a frozen worktree.

### v2.9.8 — performance and the sibling's SDRAM arbiter

**Oracle performance**, through the fixed `scripts/perf/ab_check.sh` and its
evidence rule.
- Re-measure the stale rejections: G3–G6, G9, D1, D3.
- Measure D2 (a `FrameCounter` countdown), D4 (caching `Pulse::muted`), G2
  (`#[repr(C)]` on `Ppu`), and the palette-mirror and unmapped-read leads.
- **Pacing coverage** on this host: Fifo, 60 Hz, and with run-ahead.

**Sibling.**
- **S2: a slot-scheduled SDRAM arbiter.** *Moved after v3.0.0 (maintainer,
  2026-09-30), keeping the v2.9.1 decision.* The figures this item was written
  from ("24/24" for the CPU's PRG deadline, a CHR fetch at "23 against a budget
  of 22") are v2.6.16 measurements. Since v2.9.1 put CHR in its own bank, the
  worst cases are CHR 18 of 22 and PRG 22 of 24, nothing is over budget, and
  the CHR gate's threshold was always 31. See `v2.9.8-cadence-plan.md`.
- **MiSTer OSD options that co-simulation can partly check:**
  - aspect ratio and integer scaling via `video_freak`
  - overscan crop
  - a palette choice
  - These are labelled "compiled, timing-closed, not seen on hardware".

**Libretro:** decide on `platform=libnx` (fix it or drop it).

### v2.9.9 — release candidate: re-audit, trial break, the bitstream pair

- **Re-run all four audit scopes** against the tree, as v2.9.0 did, and diff
  them against the ledgers.
- **Trial the v3.0.0 removals on a branch.** Measure the NMI-detector speed-up
  (the expected −4.1 to −4.7%) and run every gate on the trial. Also re-verify
  the removal and migration list against the tree.
- **Full seed sweeps for both builds at the RC date.** Two clean compiles of
  each must be byte-identical. This produces the RC pair.
- Prepare the libretro `.info` sync PR, but do not submit it yet.
- The sibling's oracle pin moves to v2.9.8, verified with `VERIFY=1`.
- **Sibling parity with the v2.9.5 oracle changes, under the same sweep.** The
  pin move is the first point where the DUT meets them, so the RTL lands here:
  - the `$4017` one-pulse rule in `apu2a03.sv`, gated by `apu_test_{1..10}`;
  - the odd-frame scanline-0 sprite re-arm in `ppu2c02.sv`, which moves
    `ppu-misc-sprites-on-scanline-0` from code 2 to 1;
  - the goldens where a DMA precedes a `$2002` read, where divergences should
    close (the DUT already fills the latch).
  - the four AccuracyCoin sub-test checkpoint streams (`cpu-open-bus`,
    `open-bus`, `nmi-overlap-brk`, `iflag-latency`). They are gated by verdict
    today because 3.1c dominated their bus surfaces; register them as
    checkpoint gates once the re-exported goldens carry the latch fill.

  Carried from v2.9.5 because each ends in RTL, and one sweep beats one per
  release: sibling ledger rows 3.22, 3.27, 3.31 and 3.34, and blargg MMC3
  `4-scanline_timing` sub-test 12. `chrram-fetch` waits on the oracle's
  write-placement question rather than on the pin.

### v3.0.0 — the API major, and the release-candidate core

- **ADR 0042's removals:**
  - the 19 items deprecated since 2.7.5, with their overrides and
    `dmc_dma_step_impl`;
  - the NMI edge detector, plus `oam_dma_overlap_cycle`, `dmc_step_was_get`
    and `dma_total`;
  - `serialize_header` (removal lands in the same break as `canonical_header`
    becoming private).
- **The `ab_check.sh` speed-up is part of the gate.**
- **The `LockstepBus` rename**, to the chosen name.
- **`BUS_SECTION_VERSION` 1 → 2**, with the chosen treatment of old saves.
- **The `Header` decision** (model the remaining bytes, `#[non_exhaustive]`).
- **`.fm2` Four Score P3/P4 import** (moved from v2.9.5). Carrying P3 and P4
  means `FrameInput` gains two fields. It is an exhaustive public struct that
  seven call sites build by literal, so the change is breaking and belongs in
  the API major. The `.rnm` record already stores its per-frame byte count in
  the header, so the format side is additive.
- **Docs:** every doc ADR 0042 names; a CHANGELOG migration note; ADR 0043
  referenced.
- **Bitstreams:** both, swept at the release date. The off-die name is
  finalised. Both are labelled "release candidate, not hardware-verified".
- **Libretro:** submit the `.info` upstream sync (`docs/libretro/UPSTREAM_SYNC.md`).
- **Tags:** oracle and sibling tagged together.
