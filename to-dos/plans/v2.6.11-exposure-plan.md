# v2.6.11 "Exposure" — a picture is a gate the ladder did not have

Exposure is what a photographic plate does: light falls on it and what was
already there becomes visible. Nothing changed in the DUT when the montage was
made. The defect had been there since v2.6.9.

## Measured before planning

All 141 co-simulation gates were green. Six commercial cartridges, one per
supported board, were run on both consoles and their framebuffers compared byte
for byte:

| board | game | CHR | wrong pixels |
|---|---|---|---:|
| NROM | 1942 | 8 KiB ROM | 0 |
| MMC1 | Adventures of Lolo | 32 KiB ROM | 0 |
| CNROM | Arkanoid | 16 KiB ROM | 0 |
| MMC3 | Bad Dudes | 128 KiB ROM | 0 |
| UxROM | 1943: The Battle of Midway | **RAM** | **16,565** |
| AxROM | Battletoads & Double Dragon | **RAM** | **1,702** |

The split is exactly CHR-ROM against CHR-RAM, which named the mechanism before
any tracing began.

## The deliverable

1. **The fix.** `ppu2c02.sv` exposes `chr_wr_addr = chr_addr_raw` for the
   cartridge's write port. The composite `chr_addr` — `{chr_addr_raw[13:8],
   octal_latch}` on even dots and at `pd_stage == 4` — is **correct and
   load-bearing** for fetches and for the `$2007` read path, and is left
   untouched: AccuracyCoin's `ALE + Read` and `Hybrid Addresses` depend on it.
   The two paths are separated rather than either being changed.

2. **The montage**, and the script that builds it. `tb/make_montage.sh` takes
   `--verify` and refuses to publish a tile that differs from the oracle, and
   fails closed on a missing capture rather than producing a five-tile montage
   that still looks finished.

3. **The CNROM bus conflict**, which the montage work led to: the ORACLE models
   it and the DUT did not, and every existing gate was immune BY CONSTRUCTION
   because `mkmapper.py` puts `$FF` at the select address on purpose.

4. **Two release-documentation gates**, because the same release found eight
   leads describing v2.6.10 with v2.6.9's summary.

## The gate

| # | criterion | how it is measured |
|---|---|---|
| 1 | the six render identically | **MET** — all six byte-identical over 61,440 pixels each; `make_montage.sh --verify` re-checks it at publish time and refuses otherwise |
| 2 | the fix is not a compensation | **MET** — a **control**: the pre-M10K-fix RTL differs by the IDENTICAL 16,565 pixels, so the defect predates v2.6.10 and is not its regression |
| 3 | the read and fetch paths are unchanged | **MET** — AccuracyCoin's status vector is identical entry for entry across all 146 entries, and `ALE + Read` / `Hybrid Addresses` still pass |
| 4 | no regression anywhere | **MET** — suite **142 passed, 0 failed, 0 skipped**, re-run in full for BOTH RTL changes because each reaches past the mappers (`ppu2c02.sv` touches every rung-3 gate and AccuracyCoin's 146-entry vector; `cart.sv` touches rung 7). 141 before the new gate |
| 5 | the coverage gap is stated, not implied | **MET** — three of 141 gates compare a framebuffer, all three ship CHR-ROM; `chr_wr` fires **9,600 times** in the Battletoads run, so the path was reached and never compared |
| 6 | the release-lead gates fail on the real defect | **MET** — both mutated; the chain gate then caught `bump_release.py` itself leaving two documents un-demoted |
| 7 | the CNROM bus conflict closes a real divergence | **MET** — `mapper3cnrombusconflict066` fails on two of four probes before the fix and matches on all four after, with 146 nine-field checkpoints identical; two mutations CAUGHT; `mapper3cnrom061` unaffected in both directions |
| 8 | the bitstream is rebuilt | the RTL changed, so v2.6.10's `.rbf` is superseded; timing re-verified against the reports at every corner |
| 9 | the oracle is untouched | **MET** — no chip crate changes, so AccuracyCoin 141/141 and nestest 0-diff hold by construction |

## What this release does NOT establish

- **Hardware.** No DE10-Nano and no SuperStation One are attached, confirmed by
  checking the USB bus, serial devices, removable block devices and mounts.
  Rung 6 stays open.
- **Compatibility.** Six titles is a demonstration, not a corpus, and one frame
  of each is what was compared.
- **The palette.** The montage applies it in the renderer. What the RTL emits
  and what every gate compares is the pre-palette `index_framebuffer`,
  deliberately, so a palette difference cannot masquerade as a rendering one.
- **Bus conflicts on UxROM, AxROM and NROM.** CNROM's are modelled from this
  release; the other three are not, because the ORACLE does not model them
  either and modelling them here would create a divergence rather than close
  one. That is a shared inaccuracy against hardware on mapper 2, named rather
  than fixed on one side.

## Risks

1. **A montage invites a claim the project cannot support.** Mitigated by the
   README section stating what the picture is not, in the same block as the
   picture.
2. **The frame choice is arbitrary and could hide a defect.** True, and named:
   one frame each. *Bad Dudes* at 400 frames is a blank frame on BOTH sides, and
   `fb_to_png.py` says so out loud rather than drawing a black rectangle that
   would have entered the montage looking like a rendering failure.
3. **The two new documentation gates could go inert.** Both fail closed on an
   empty corpus, and `chain_docs()` is derived from `ANCHORS` rather than
   hand-listed — the hand list was wrong on its first use, missing `SUPPORT.md`
   and `SECURITY.md`.
