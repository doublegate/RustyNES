# v2.9.6 "Roster" — the popular missing mapper families, and the GTROM promotion

The third release of the line to v3.0.0
([line plan](v2.9.4-to-v3.0.0-line-plan.md), v2.9.6 row). v2.9.5 closed the
accuracy backlog; this release widens the mapper table.

## Maintainer decisions (2026-09-30)

| Question | Decision |
| --- | --- |
| Codename | **Roster** |
| Tier of the new families | **Per page.** A family is Curated where its NESdev page gives exact register masks. It is BestEffort where the page says "probably" or "unknown", or has only Disch's notes. Each verdict is recorded in `docs/mappers.md` |
| GTROM (111) | **All three documented features, plus `.sav`.** The register window becomes `$5000-$5FFF` / `$7000-$7FFF` only. The 8 KiB of bonus RAM at PPU `$3000-$3EFF` is added. SST39SF040 self-flashing is emulated, and flashed sectors persist through the battery-save path. The flash model is shared with UNROM 512 (mapper 30) |
| Breaking changes | **Allowed** (save states included), "whatever is necessary to make everything complete and fully functional". Every changed save format still bumps its own version, so an old state fails with a clear error and is never misread |

## Provenance

Every family here is written from its vendored NESdev page
(`nesdev_wiki/output/INES_Mapper_NNN.md`, `GTROM.md`, `NES_EVENT.md`,
`MMC3.md`) and from public datasheets (SST39SF040). No reference-emulator
source is read.

`mmc3_clones.rs` carries a Mesen2 derivation record ("MMC3 variants"), so the
new MMC3-based boards do **not** go into it. They get a new module,
`mmc3_boards.rs`. It wraps the project's own Nintendo MMC3 (`m004_mmc3.rs`, no
provenance header) through `pub(crate)` accessors.

The remaining edits all stay outside a recorded region:

- `m016_bandai_fcg.rs`: mapper 153. Its derived region is the EEPROM, which
  153 does not use.
- `homebrew_boards.rs`: GTROM and UNROM 512. The file has no header.

## Gates

- **Red first, per family.** A unit test from the page's register table fails
  before the board exists (`parse` rejects the id), then passes. Where a board
  has several documented behaviours (lock, outer masks, IRQ direction, open
  bus), each gets its own assertion.
- **Mutation proof.** For each family, reverting one documented behaviour
  (an outer mask, the IRQ direction, the protection index) is CAUGHT by a
  named test.
- **Boot fixture.** A synthetic CC0 program, built in the test from the
  register description, runs through the full `Nes` path. It checks, per board:
  - that banks switch where the page says;
  - that the IRQ fires, for boards with an IRQ;
  - that the board survives a save-state round-trip mid-run.
- **GTROM.**
  - A generated CC0 ROM writes and reads back bonus RAM at PPU `$3000`.
  - It checks that a `$6000` write does not change the register.
  - It checks that a sector erase plus byte program is visible after reset.
  - It checks that the flashed image survives a `.sav` round-trip in the
    frontend battery path.
- **Tier table.** `tier.rs` classifies all 16 new ids. The Core / Curated /
  BestEffort lists in its tests and in `docs/mappers.md`, `docs/STATUS.md` and
  `README.md` agree. The family count goes from 174 to 190.
- **Honesty gate.** `mapper_tier_honesty.rs` and `v21_best_effort_sweep.rs`
  pick up the new ids automatically. The new BestEffort ids join the sweep.
- **Sweeps.** `prg_ram_window_open_bus.rs` and
  `every_board_snapshot_carries_cartridge_ram` cover every new id.
- **Standing gates:**
  - fmt;
  - clippy, for every feature set and all three wasm builds;
  - rustdoc `-D warnings`;
  - the no_std build;
  - the full `--features test-roms` suite, with its count;
  - AccuracyCoin 144/144 and nestest 0-diff;
  - the release audits.

## Risks

- **MMC3 accessors.** The new boards reach the MMC3 through `pub(crate)`
  accessors. `Mmc3`'s own hot path must not change. AccuracyCoin, the MMC3
  battery and the commercial MMC3 corpus are re-run.
- **PPU nametable addressing.** GTROM's bonus RAM needs the unfolded
  `$3000-$3EFF` address. Only the `$2007` path produces it, since rendering
  fetches never reach `$3xxx`. The change is scoped to a new defaulted mapper
  hook, so the other 173 boards see the address they see today.
- **Battery path.** GTROM's `.sav` is the full 512 KiB flash image, which
  exposes it through `sram()`. The RAM sweeps assume `sram()` is `$6000` RAM,
  and they are checked.

## Out of scope

- Hardware: v3.x.
- The sibling RTL: its mapper breadth is after v3.0.0. This release changes no
  RTL, so v2.9.2's bitstream pair ships byte for byte.
- Performance: v2.9.8.
