# v4.x: the power-user line (D33)

Drafted 2026-10-17 from the maintainer's D33 selection. These are the large items of that
selection; the small and medium ones are in the v3.5.0-v3.9.0 plans. The slots are proposals:
each release is planned in full when its predecessor ships, and two items
(`T-TAS-CONSOLE-VERIFY`, `T-STATE-SHARED-MISTER`) wait on the hardware release (D29), since
no MiSTer bitstream has run on a board yet.

| Slot | Ticket (size) | Item | Gate |
| --- | --- | --- | --- |
| v4.1.0 | `T-DEBUG-REVERSE` (L) | Reverse debugging: reverse step and reverse watchpoints ("run back until $07A0 changes") by checkpoint and deterministic replay, and backward dataflow queries that extend Pixel Provenance past the CPU write to where the value came from | Reverse-continue stops at the same write a forward watchpoint found; a pixel's chain is followed back through RAM to its computing instructions |
| v4.1.0 | `T-NETPLAY-CROSSPLAY` (M-L) | Browser-to-native cross-play: a browser peer and a desktop or Android peer in one rollback session over WebRTC on both sides, through the hosted TURN | A browser and a native peer complete 600 confirmed frames with matching digests; wasm audio determinism pinned by a golden test first |
| v4.2.0 | `T-TAS-CONSOLE-VERIFY` (L) | Console verification: TAStm32 export with per-poll (sub-frame) input and a declared power-on RAM model, and a three-way check (software, the MiSTer RTL's per-frame CRCs, a real console) | An exported movie replays on a real NES through TAStm32 to its end; the MiSTer leg reports matching CRCs (after the hardware release) |
| v4.2.0 | `T-STATE-SHARED-MISTER` (L) | One save-state format shared by the MiSTer core and the software (pause on MiSTer, continue on a phone), designed from RustyNES's own state spec and RTL only, plus content-addressed cross-device state sync | A state saved on the MiSTer loads in the software core and continues bit-exactly, and the reverse (after the hardware release) |
| v4.3.0 | `T-VIDEO-PPU-INTERP` (L) | PPU-level frame interpolation for 120/240 Hz displays: midpoint frames re-rendered from interpolated sprite and scroll positions, per-game opt-in, falling back on raster effects | Interpolated frames never alter the emulated output (digests unchanged); a raster-effect game falls back automatically |
| v4.3.0 | `T-A11Y-NARRATION` (M) | Accessibility: game-state narration from RAM through per-game schemas (OCR only as a fallback), colour-vision remaps of the 64-colour palette per deficiency type, and RAM-triggered assist modes outside hardcore | Narration fires on scripted state changes in a test ROM; the palette remaps keep emphasis bits; assists are refused in hardcore |
| v4.4.0 | `T-EDU-EXPLAIN-FRAME` (M-L) | "Explain this frame": a dot-level timeline of CPU events, PPU fetches and mapper IRQs beside the co-simulated RTL waveform, and interactive wasm lessons on the real core | The software timeline and the RTL waveform agree on every event of a reference frame |
| v4.4.0 | `T-DEBUG-MOBILE-WEB` (L) | Full debugger parity on Android, iOS and the web (not read-only): breakpoints, stepping, memory editing, the PPU and APU viewers | The desktop debugger's panel test list runs against each platform's debugger surface |
| v4.5.0 | `T-RL-ENV` (M) | A vectorised reinforcement-learning environment: PyO3 Gymnasium, N headless instances, cheap state forks, deterministic seeds, cycle-accurate (with an honest throughput benchmark) | Episodes replay identically from their seeds; throughput is measured and published against a stated baseline |

## Order and dependencies

- v4.1.0 builds on the rewind ring and Pixel Provenance (`T-DEBUG-REVERSE`) and on the hosted TURN
  and WebRTC lobby (`T-NETPLAY-CROSSPLAY`).
- v4.2.0 needs the hardware release's board session: the console leg of `T-TAS-CONSOLE-VERIFY`
  and both directions of `T-STATE-SHARED-MISTER` are measured on hardware.
- v4.3.0's narration uses the per-game RAM schemas `T-GHOST-RACE` and `T-SPEEDRUN-MEMIF` start.
- v4.4.0's web debugger shares its surface with the mobile one; `T-EDU-EXPLAIN-FRAME` reuses the
  co-simulation harness's waveform output.
- v4.5.0's environment reuses `T-MCP-SERVER`'s headless fork API.

## Out of scope

- A zero-knowledge proof of play (no_std chip crates as a zkVM guest): researched, not selected;
  the cycle-accurate core makes proving very costly. `T-LEADERBOARD-SIGNED`'s bisection is the
  practical form.
- Distributing ROMs, packs derived from commercial art, or DAT files.
