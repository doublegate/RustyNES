# v3.5.1: the v3.5.0 review residue, and the MMC5 outside rendering

A patch release on the v3.5.0 "Chorus" line, written on 2026-10-23. The
codename is asked at the cut.

## Branch point

v3.5.1 is built on `feat/v3.5.1`, cut from `origin/main` at `3d02b99d` (the
v3.5.0 post-release PR, #625). The maintainer asked for it to be committed and
not pushed (2026-10-23), so v3.6.0 is built on top of this branch rather than
on `origin/main`: v3.5.1 must merge first, and any change review makes to it
means rebasing v3.6.0.

## What the MMC5 fix moves (measured)

- `test-roms` + `commercial-roms` on the fix: `external_real_games` 60/0
  (Castlevania III, Bandit Kings of Ancient China and Uchuu Keibitai SDF
  among them), `external_extended` 169/0, `external_coverage` 6/0,
  `epoch_fingerprint` 2/0, `mmc5` 3/0, `mmc5_scanline_irq` 4/0. No snapshot
  or fingerprint moved.
- A temporary probe (removed; the mapper restored from a snapshot) counted
  every CHR access where the pre-fix latch would have chosen a different
  bank, over 3,600 frames of each of those three games with Start and A
  pulsed every 240 frames: 0, 0, 0.
- So `EMULATION_EPOCH` stays 6 (the rule's trigger is a moved golden or
  snapshot). Residual risk, stated: a v3.5.0 movie of a Koei game that
  reaches a screen reading CHR through `$2007` in vertical blank after an
  extended-attribute frame would replay differently; none of the measured
  play reaches one.

## Residue verdicts

| Suggestion | Verdict | Evidence |
| --- | --- | --- |
| A device key's held state across a rebind | **Confirmed, fixed.** `reload_bindings` replaced the key map and kept the held state, so a key held while it was rebound stayed held: its release no longer mapped to the position its press set. A reload now releases every keyboard-held input (`InputState`) and the app clears the Family BASIC matrix | `a_rebind_releases_what_the_old_binding_held` failed before the fix |
| `lua_eval` from the MCP server during a real-time run | **Refuted.** Each runner frame and each tool call take the same session mutex, so an eval sees one frame boundary and the runner waits; the breach check compares two snapshots taken under that lock, and the runner's "fell behind, run on" path absorbs the stall | Pinned in `real_time_running_pauses_and_stops_at_breakpoints`: an eval mid-run answers `ok` with the state unchanged, and the run's journal still replays (`movie_verify` identical) |
| Unbounded reads of user-chosen ROM, patch and splits paths | **Confirmed, fixed.** Every user-named file was a bare `fs::read`: a FIFO blocks in `open`, a device such as `/dev/zero` streams for ever. `bounded_read` refuses a non-regular file from the metadata (following symlinks) and reads at most 64 MiB plus one byte | Unit tests over a device, a symlink to it, a FIFO, a directory and the limit's edge; applied at 22 sites (ROMs, patches, FDS BIOS, movies, TAS projects, symbols, source maps, scripts, palettes, splits, the per-game sidecar, the CLI's verify and speedrun) |
| Sibling: the dead `x_hit_q` register | **Confirmed, removed.** Registered, read only by an `unused_x` sink | The netlist loses one register with no fanout |
| Sibling: `nt_ovr` and the IRQ not gated by the board select | **Refuted as a defect, documented.** The registers that drive both are written only while `active` and reset to off, and a saved state is refused for a different ROM, so no other board can see either asserted. Gating the outputs would add no reachable behaviour; the reasoning is recorded at the site so a mutation's NOT CAUGHT is expected | Site comments in `mmc5.sv` |

## Out of scope

- New bitstreams. The RTL changes are compiled and timed at the release cut,
  on the release commit, as every release does; a compile now would carry an
  earlier date than the release.
