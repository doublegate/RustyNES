## Entry item (added 2026-11-12)

| # | Item | Gate |

| E1 | `T-MISTER-FITTER-PRESSURE` with `T-MISTER-VRAM-M10K`. Three questions: why the seed-to-seed spread on one RTL is about half a nanosecond; what fills the on-die build's block memory (65% of its bits, `c0bba2c`); and how the nametable moves from 16,384 register bits to block RAM, with a port plan that keeps every read's latency | Both ladders give unchanged verdicts after the M10K move. Then an eight-seed sweep, on one RTL and one BUILD_DATE, closes both builds at a majority of seeds, or the ticket records, with measurements, why that is not reachable without further RTL changes. **Why it comes first.** Measured so far:

- **v3.6.2** (sibling `7bfc8c1`, 261107): one seed in eight closed both
  builds.
- **The v3.7.0 release sweep** (`c0bba2c`, `RustyNES.qsf`, 261111): the
  on-die build closed at none of seeds 1-8, though it carries no FDS. Of
  seeds 1-16, only 11, 12 and 15 closed both builds, and 15 shipped.
- **After the review fixes** (`0635bd5`), the 261112 sweep was still running
  on 2026-11-12. On the raw Quartus logs of its twelve finished compiles,
  not yet put through `check_timing`, one closes: on-die seed 5.
- **The worst path in each case is the framework's HDMI scaler clock**
  (`pll_hdmi`), not the core. A smaller or better-placed core may still be
  what frees it.

Rows 6-9 each add RTL, and row 9 is the VRC7's FM synthesis. Starting them
on a design that closes at one seed in eight or fewer would turn every
release sweep into a search.

**Row 5a, rows 11 and 12.** The v3.7.0 review measured two departures
(sibling `b4eda18`, recorded in `3aef852`) at places the NESdev pages do not
address at all:

- **11.** A read resumed just before a run of `$00` bytes. The oracle passes
  over them; the MiSTer core delivers them.
- **12.** A block overwritten from inside, then read back past its old
  length. The oracle returns the bytes as written with no CRC; the MiSTer
  core synthesises a CRC at the length the header gives.

Each was found by black-box bus-trace comparison with the pinned oracle
`9c62143c`. Ledger 3.137 lists four options, with what building each would
take:

- A, keep the MiSTer core's behaviour (**chosen by the maintainer,
  2026-11-12**: record both, build neither);
- B, match the oracle;
- C, an OSD option defaulting to A;
- D, settle it on hardware evidence (D29).

Item 12 is a disk-format question as well as RTL, because the `.fds` image
stores no CRCs. The trigger to reopen either one is a game or disk tool that
resumes inside a block or reads back an in-place overwrite, or hardware
evidence. Until then neither row gets an oracle change either: the oracle's
answer there is no better evidenced than the MiSTer core's.

## Maintainer settings (not release items)

From the 2026-11-12 CI cost audit (`docs/agents/ci-and-release.md` on #650).
Both are repository or account settings, which only the maintainer can
change.

- **Copilot code review effort.** Copilot review is the repository's only
  real cost: October's Actions netted $0 on a public repository, against
  7,574 Copilot credits. The audit names the effort level and the "use custom
  instructions" toggle as the levers. GitHub's documentation puts Lite at
  about $0.25 a review and Balanced at $1.50. The proposal is Lite.
- **The sibling's Dependabot runner** is set to a labelled runner that no
  runner carries, so Dependabot has never run there (sibling branch
  `ci/actions-cost-2026-11`). The proposal is to set it back to
  GitHub-hosted.

## Risks

- **E1 may not converge.**
  - The worst path is in the framework's HDMI scaler, so changes to the core
    move it only indirectly.
  - One changed RTL line has moved a seed's margin by about 0.5 ns (v3.6.2).
  - If E1 ends without a majority, the ticket says so, and F4c starts on the
    evidence. A 9-16 sweep, as at v3.6.0 and v3.7.0, is the release fallback.
- **The M10K move changes read latency** unless the port plan holds. Both
  ladders, the fingerprint and the off-die SDRAM gates are what show it.
- **Two derived regions in one release.** Row 8 (`blip.rs`) and row 9
  (`opll.rs`) are both Provenance-headered. The pull toward rung 4 is
  strongest exactly when the DUT and the oracle disagree; rung 4 needs an ADR
  0037 amendment first, naming the maintainer.
- **Row 5a moves frames and samples.** Confirmed rows raise the epoch once,
  and the MiSTer FDS goldens are re-exported in the same change. The
  sibling's FDS gates then re-run against the new pin.
- **`T-GHOST-RACE` uses the live lobby Worker**, a cost and abuse surface:
  rate limits and the kill switch come first, as for v3.4.1 and v3.7.0.
- **Review cost per PR.** Every review-triggering PR costs Copilot credits.
  Four of eighteen oracle reviews in a month were post-release docs or fix
  PRs (the audit), so the release is cut as one PR per repository.
