# v2.8.2 "Solder" — the MiSTer core's on-die RTL, corrected against the oracle and the wiki

The third release of the v2.8.x line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.8.x-libretro-rtl-audit-plan.md)). It works from
[`rtl-audit-report.md`](../../docs/audits/rtl-audit-report.md) §3.1 to §3.5
and the [RTL ledger](../../docs/audits/rtl-disposition.md) rows targeted at
v2.8.2. Both repositories change: the sibling's RTL and co-simulation ladder,
and one oracle mapper found wrong while triaging.

## What v2.8.1 closed and did not

v2.8.1 "Gasket" closed the libretro ledger. The RTL ledger had eleven rows
targeted at v2.8.2, nine of them UNTRIAGED; the audit's RTL report is the one
its own calibration trusts least.

## The deliverable

Every v2.8.2 row triaged against the nesdev wiki and a first divergence
against the oracle, and every CONFIRMED row fixed with a gate that fails
first and catches its mutant. Written from documentation under the ADR 0037
firewall; no reference HDL or emulator source was opened. The provenance
headers were checked before any oracle source was read for this work
(`m001_mmc1.rs`, `pulse.rs`, the triangle and noise channels carry none).

## The gate

- Each fix: its gate red on the unfixed RTL, green after, and the fix's
  mutant caught by that gate (a value mutant where a deleted signal would be
  a Verilator build failure rather than a result).
- The whole ladder (`tb/regress.sh`) green from the sibling tree, with the
  `TOTAL:` line recorded; `make -C tb lint` clean.
- A Quartus compile of the changed RTL at the pinned seed 4 whose timing
  closes (`scripts/check_timing.py`), since any RTL change makes the
  published `.rbf`'s timing report stale.
- Oracle: `--features test-roms` suite, AccuracyCoin 144/144, nestest 0-diff
  re-run for the MMC1 change.
- After the oracle merges, the sibling's `tb/ORACLE_COMMIT` moves to the
  merge commit and `VERIFY=1 tb/fetch-goldens.sh` re-verifies every golden
  against it.

## What was found and done

| Row | Verdict | How it was shown |
| --- | --- | --- |
| R-3.5a MMC1 reset vs the consecutive-write filter | INVERTED | nesdev MMC1: a reset is never ignored, only a data write on the cycle after a write. The RTL was right; the ORACLE ignored the reset. Oracle fixed (red unit test, mutation caught); sibling stimulus `mapper1rmw068` (an `INC` on the serial port) pins the RTL against the corrected oracle |
| R-3.5b MMC3 `$E000` vs a same-edge counter clock | FIXED | `cart-mmc3-gate`, a module gate placing both on one master clock: pending stayed set with IRQs disabled. "Permanently stuck" overstated: it lasts until the next `$E000` |
| R-3.5c MMC3 Sharp reload-to-zero | NOT A DEFECT | the RTL implements the "normal" (Sharp) revision; the report attributes the wrong one. Covered by the gate's `reload-to-zero` case |
| R-3.5d SNROM PRG-RAM protection | FIXED | `mapper1snrom067`: 3,924 cycles diverged before, 0 after |
| R-3.2a `vblank_now` vs `suppress_vbl` | NOT A DEFECT | needs `$2002` reads on dot 0 and dot 1 of one frame; CPU accesses are three dots apart |
| R-3.2b `$2002` open-bus latch | FIXED | `ppulatch072` (a 13-cycle loop, coprime with the frame, so every landing dot is reached): 2 cycles diverged before, 0 after |
| R-3.3c triangle / noise reload vs a length clock | FIXED | first-divergence read against the oracle; `aputrireload070` / `apunoisereload071`, each channel's mutant caught only by its own gate |
| pulse-1 sweep negate | GATE ADDED | `apusweepneg069` guards the v2.7.0 oracle fix; a mute mutant diverges on 163,968 cycles |
| R-3.1a / R-3.1b CPU `last_cycle`, NMI entry | PARTIAL, unchanged | no gate shows an effect; revisited at the v2.9.0 re-audit |

## Risks

- The oracle's MMC1 change is an emulation behaviour change. Its reach is
  the reset-after-write case only; the test-roms suite and AccuracyCoin are
  re-run on it.
- The sibling's goldens are pinned at an oracle older than every fix here.
  Until the pin moves, the new stems' goldens come from the release branch;
  the pin bump re-derives all of them.

## Out of scope

- RTL robustness (reset synchronisers, the `dec_rom` mux, `rmw_addr`,
  tabs): v2.8.3.
- The off-die SDRAM build: v2.8.4.
- Anything on hardware: v2.9.2. **No hardware has run any bitstream.**
