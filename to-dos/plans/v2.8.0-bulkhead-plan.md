# v2.8.0 "Bulkhead" — the libretro core stops a fault at its own boundary

The first release of the v2.8.x line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.8.x-libretro-rtl-audit-plan.md)). It works from
[`libretro-audit-report.md`](../../docs/audits/libretro-audit-report.md) §1,
§2.1, §2.2 and §2.4, and the
[libretro ledger](../../docs/audits/libretro-disposition.md) rows targeted at
v2.8.0 (L-1.1 to L-1.5, L-2.1, L-2.2, L-2.4). Oracle only; the MiSTer sibling
does not change. It also ships the buildbot work contributed in #554, which is
already under `[Unreleased]`.

## What v2.7.5 closed and did not

v2.7.5 closed the v2.7.x line: the core and frontend ledgers have no untriaged
row. The libretro ledger has fourteen: every row except the five triaged while
planning.

## What planning found before any code

Three findings change the shape of the audit's remediation, and each is recorded
because the audit's own fix would have been wrong without it.

1. **The shipped libretro core aborts on panic, so `catch_unwind` does nothing
   in it.** `[profile.release]` sets `panic = "abort"`, and the libretro core
   is built with `--release` on every path (the crate `Makefile`, the libretro
   buildbot's fixed `cargo build --release --target <triple>`, the GitHub
   `libretro-cross` gate). Under abort a panic ends the process before any
   unwinding, so the audit's Fix 9 would pass every test (tests unwind) and
   change nothing a RetroArch user runs. This is the v2.7.4 MOB-03 finding
   again, on a different artefact. Containment therefore needs two halves:
   remove the panics our layer can remove, and build the core with
   `panic = "unwind"` so the guard around what remains is live.
2. **The audit's Fix 9 conflicts with its own Fix 5.** Fix 9 drops the console
   (`self.nes = None`) after a panic. The frontend still holds the WRAM and
   SRAM pointers `register_memory_maps` handed it, so dropping the console is
   exactly the use-after-free §1.3 describes. A contained panic must keep the
   allocations alive and stop running them: the console is *poisoned*, not
   dropped, and the pointers stay valid until the frontend unloads the game.
3. **`rust-libretro` is unmaintained.** 0.3.2 (2023-02-27) is its last release
   and its repository has not been pushed since that day. An upstream PR is not
   a remediation path anyone can plan on. Which of its hazards are reachable
   from RetroArch's call order and ours is assessed below; the choice between a
   vendored patch and accepting the residue is recorded, not made silently.

## The deliverable

| Id | Item | Plan |
| --- | --- | --- |
| L-1.1 | Panic containment | Remove the seven `.expect` sites on the run path; wrap every `Core` callback that runs emulation in `catch_unwind`; poison, never drop, on a caught panic; build the core with `panic = "unwind"` on every libretro build path |
| L-1.2 | `_game` fallback | Use the standard `retro_game_info` when `GET_GAME_INFO_EXT` is refused; validate null data and zero size on both paths |
| L-1.3 | Memory-map deregistration | Hand the frontend an empty map before the console is dropped on unload |
| L-1.4, L-1.5 | Upstream `rust-libretro` hazards | Assessment of reachability; `on_deinit` releases our buffers; anything reachable only through the upstream crate goes to the maintainer as vendor-or-accept |
| L-2.1 | `serialize_size` headroom | Size from the largest expansion-device encoding, exported by the core, and zero the tail on every serialize |
| L-2.2 | Trailing padding | `SectionIter` ends at an all-zero tail; any non-zero byte still errors |
| L-2.4 | `internal_data_bus` | Appended to the `BUS` section under the trailing-default pattern (pre-v2.8.0 blobs decode with it equal to `open_bus`) |
| — | The schema audit covers the bus | `snapshot_schema_audit` audits CPU, PPU, APU and the OPLL, not `LockstepBus`, which is why this field was missed. The bus is added, and every one of its fields classified |

## The gate

- **A C-ABI harness.** The libretro crate's tests drive the exported
  `retro_*` functions through a test frontend (an environment callback that can
  refuse `GET_GAME_INFO_EXT` and records `SET_MEMORY_MAPS`), because the
  defects are all at that boundary and a test of `RustyNesLibretro`'s methods
  cannot see one. Each of these fails on `main` first:
  - a frontend that refuses `GET_GAME_INFO_EXT` loads a ROM;
  - with a Zapper on both ports, `retro_serialize` succeeds into a
    `retro_serialize_size` buffer, and the padded blob unserializes;
  - after `retro_unload_game` the last recorded memory map is empty;
  - a panic injected inside `retro_run` returns, later calls are inert, and the
    registered pointers still address live memory.
- **Core:** `SectionIter` accepts a snapshot followed by 1 to 64 zero bytes and
  rejects the same with one non-zero byte; `internal_data_bus` round-trips; a
  pre-v2.8.0 `BUS` body still decodes.
- **The audit:** `snapshot_schema_audit` lists the bus, and fails on `main`
  with `internal_data_bus` among its unaccounted fields.
- **Mutation:** each fix reverted in isolation turns its test red.
- The full CI set, `cargo test --workspace --features test-roms` 0 failed,
  AccuracyCoin 144/144 and nestest 0-diff (the bus section changes).
- **The unwind profile's cost measured** on the libretro frame path before it
  ships, and recorded either way.

## Risks

- Building the libretro core with `unwind` touches every buildbot job, and six
  of them (Apple, Android, webOS) cannot be run here. Unwinding is Rust's
  default on each of those targets and their prebuilt `std` ships
  `panic_unwind`, so the risk is low but not zero; the GitHub `libretro-cross`
  gate rehearses the Linux, Windows and armv7 triples.
- A trailing-default field of one byte cannot be told from its own absence, so
  a v2.8.0 `BUS` body truncated by exactly one byte decodes as a legacy one.
  The section's length header makes that reachable only from a crafted file.

## Out of scope

L-2.3 and the rest of v2.8.1 (build, metadata, input, blit, audio). The
`restore_quiet` path `retro_unserialize` uses skips the MOB-08 rollback, so a
foreign state that fails mid-restore leaves a half-applied machine; that costs
a snapshot per unserialize on RetroArch's run-ahead path, so it goes with the
v2.8.1 serialize work where it can be measured. The RTL (v2.8.2 onward).

## Progress (2026-09-25)

Paused on 2026-09-24 for the v2.7.6 measurement release and resumed on
v2.7.6's `main`.

- **Done:** the zero-padding rule in `SectionIter` (L-2.2, core half);
  `internal_data_bus` in the `BUS` section (L-2.4); the bus added to
  `snapshot_schema_audit`. All red first.
- **Harness built:** `src/abi_tests.rs` drives the exported `retro_*`
  functions. A test for WRAM staying put across a restore passes and stays as
  a guard.
- **L-1.3 and L-2.1 fixed**, each red first in the harness (the last map after
  unload still had 3 descriptors; serialize failed with a Zapper on both
  ports). `rustynes_core::SAVE_STATE_DEVICE_HEADROOM` (26 bytes) is added to
  `retro_serialize_size` and the unused tail zeroed. Four mutations, all
  caught: no deregistration, no headroom, tail not zeroed, the device maximum
  at 13.
- **L-1.2 fixed** (maintainer decision 2026-09-25: vendor the patched binding).
  `vendor/rust-libretro-sys` blocklists the generated `retro_game_info` and
  defines it by hand; `on_load_game` falls back to it. Red first; removing the
  fallback turns the test red, and the unpatched binding does not compile.
- **Next:** L-1.1 (remove the `.expect`s, `catch_unwind` with poisoning, and
  the unwind cost measured), `on_deinit`, and the L-1.4 / L-1.5 assessment.
- **L-1.2 is blocked, and needs a decision.** `rust-libretro` 0.3.2's
  `retro_game_info` is an opaque one-byte struct: libretro.h forward-declares it
  before defining it, and bindgen kept the placeholder. `retro_load_game`
  passes `Some(*game)`, so the core never receives `path`, `data` or `size`, and
  the audit's fallback cannot be written from this side. (Already known when
  the core was written: `docs/libretro/WALKTHROUGH.md` records the opaque struct
  as the reason the core reads `GET_GAME_INFO_EXT` instead.) The options are a
  vendored copy of `rust-libretro` with the struct fixed (MIT, compatible, but a
  vendored third-party tree and a `NOTICE` entry), or accepting that frontends
  without `GET_GAME_INFO_EXT` are unsupported. The crate is unmaintained, so an
  upstream fix is not an option to wait on.
- **RetroArch checked for L-1.3** (its `runloop.c`): memory maps are kept until
  the core is torn down, and an empty map clears them. The fix is sound.
