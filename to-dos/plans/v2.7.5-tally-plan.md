# v2.7.5 "Tally" — performance claims measured, dead interfaces marked

The sixth and last release of the v2.7.x audit line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.7.x-core-frontend-audit-plan.md)). It works from
[`core-audit-report.md`](../../docs/audits/core-audit-report.md) §3 and §4 and
the [core ledger](../../docs/audits/core-disposition.md) rows still open for
v2.7.5, plus two carry-ins: frontend MOB-06 (deferred from v2.7.4) and the
HD-pack budget refund agy found on #551. Oracle only; the MiSTer sibling does
not change.

## What v2.7.4 closed and did not

v2.7.4 closed every mobile finding except MOB-06, the per-frame framebuffer copy
through UniFFI, which is a performance change and needs a measurement like the
others. Everything in the core ledger outside §3 and §4 is closed.

## The deliverable

Two halves with different gates.

**Performance (§3.1 A/B/C, IMP-04..07, IMP-12, §3.5b, §3.6, MOB-06).** Each is
a claim to measure, not a change to make. The project's evidence is heavily
against micro-optimisation of this core: `docs/performance.md` records the
v2.3.1 G-campaign (ten items, none adopted, "the per-dot loop has no incidental
overhead left to reclaim"), `#[inline]` on the hot bus functions at +0.60%
(a regression), and the APU D-series nulls. So every item starts with a
**ceiling probe** where one exists: delete the work, knowingly breaking
correctness, and measure the upper bound. A zero ceiling rejects the item in
one run with no correctness risk. An item is adopted only under `ab_check.sh`'s
rule: a reproduced, statistically clean gain on the shipped workloads, a clean
A/B/A order-bias control, no mixed signs, and byte-identical output.

**API and documentation hygiene (§4.2-§4.4, §4.7).** Measured before marking:
the audit's list of 22 dead `rustynes_cpu::Bus` methods was checked by the
compiler (every trait method temporarily `#[deprecated]`, the workspace and
every CI feature set checked). **18 are dead, and 5 of the audit's 22 are
live**: `cpu_read` / `cpu_write` (the trait's default `read` / `write`, and the
core's own calls), `on_cpu_cycle` (the default `cpu_clock` a stub bus uses),
`dmc_dma_defer_load_entry` and `oam_dma_overlap_cycle` (the core calls both).
Two the audit missed are dead or feature-live: `internal_data_bus` has no
caller; `trace_instr` is called under `cpu-instr-cycle-trace`.

## The gate

- Performance: per item, a ceiling (or candidate) run and a second independent
  run under `scripts/perf/ab_check.sh`, recorded in `docs/performance.md`
  adopted or rejected with its numbers.
- Any adopted change: `cargo test --workspace --features test-roms` 0 failed,
  AccuracyCoin 144/144, nestest 0-diff, and the goldens byte-identical.
- Hygiene: the workspace, every CI feature combo and both wasm32 targets build
  with `-D warnings` after the deprecations (a deprecated method still called
  anywhere fails the lint, so the build IS the proof of deadness).
- The HD-pack refund: a red-first test (a truncated PNG then a valid one at an
  exact budget).

## Risks

- **Measurement noise exceeds most expected effects.** Mitigated by the ceiling
  probe first, the A/B/A control, and the mandatory second run.
- **Serialisation.** Benchmarks need an idle machine, so the perf campaign runs
  last and alone; hygiene builds first.
- **MOB-06 cannot be measured here.** Its cost is Android / iOS allocation and
  GC, which no desktop bench reproduces. If no device-free measurement is
  possible it is recorded as not measurable here rather than changed blind.

## Out of scope

Removing any deprecated item (v2.9.0 decides, per ADR 0041). The v2.8.x
libretro and RTL audits. Capping `BlipBuf`'s buffered samples (IMP-07's second
half): every host drains each frame, so the cap bounds nothing real, while the
one accumulating consumer (the probe engine's undrained framebuffer trials,
about 24,000 samples over 30 frames) would have its audio silently truncated;
the drain contract stays "kept until drained".
