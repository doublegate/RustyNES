# v2.9.7 "Tandem" — the desktop's features on web and mobile

The fourth release of the line to v3.0.0
([line plan](v2.9.4-to-v3.0.0-line-plan.md), v2.9.7 row). v2.9.6 widened the
mapper table. This release closes gaps between the platforms: features the
desktop has that web and mobile lack, a Settings field that does nothing, a
Lua call that is only logged, and release binaries that leave out half the
native features.

## Maintainer decisions (2026-09-30)

| Question | Decision |
| --- | --- |
| Codename | **Tandem** |
| Release binaries | **`full` becomes the default release binary.** There is one archive per platform, built with `--features full`. The Cargo default feature set does not change: `full` is native-only, and the wasm build and every `cargo build` keep today's defaults |
| i18n depth | **User-facing panels only**: Settings, the shell, input rebinding, netplay (native and the wasm lobby), cheats, and the ROM info and header editor panels (about 220 strings). Debugger-internal panels stay English. The Spanish is machine-drafted and marked for native review |
| Extras | **All three.** (1) Stage the six local MC-ACC titles and StarTropics II as real-game evidence for mapper 4 submappers 3 and 1. (2) Take `T-COMMERCIAL-GARBLE`. (3) Keep `T-MAPPER-DUMPS` open until the library is reachable |

## What the survey found before any code

- **The `pacing_mode = "vrr"` item is already done.** v2.3.3 gave VRR the same
  sustained-miss fallback to wallclock as display sync (`app.rs`, see
  `docs/performance.md` "vrr had no sustained-miss fallback"). It is closed with
  that citation, and no code changes.
- **`client.frameskip(n)` is registered** in the Lua `client` table and queues
  `ClientCmd::FrameSkip`. The frontend only logs "not yet supported".
- **The core already snapshots a Vs. DualSystem** (`VsDualSystem::snapshot`,
  `restore`: an "RVSD" container). The desktop's F1/F4 simply return when a
  cabinet is loaded, without even a status message.
- **Mobile has no FDS, NSF, DualSystem or SOCD switch.** Opposite-direction
  cancel is applied in the Kotlin and Swift input code, always on.
- **Web has no battery-save persistence.** It already stores save states in
  IndexedDB (`wasm_idb.rs`).
- **Nothing calls `Nes::set_extra_scanlines`.** The Settings "Overclock (extra
  scanlines)" field saves a value that nothing reads.
- **The library root** recorded in `scripts/coverage/.library-index.json`
  (`~/Dropbox/ROMs/...`) does not exist on this machine. `~/Emulation/roms`
  holds 473 dumps, none of them the 17 v2.9.6 families. It does hold six
  Acclaim titles headered as mapper 4 submapper 3 (MC-ACC) and StarTropics II
  (submapper 1, MMC6).

## Rules for this release

- Everything touching a default stays off by default, except where a decision
  above says otherwise. AccuracyCoin 144/144 and nestest 0-diff are re-run.
- Mobile and web behaviour that cannot run on this machine (iOS Swift, a real
  browser, a device) is never reported as verified. It gets a row in
  `docs/mobile-v2.9.3-run-sheet.md` or a manual line in the notes.
- Provenance: nothing here needs reference-emulator source. The MMC5 and 250
  work reads only the NESdev pages; `mmc5`'s file header is checked before any
  edit.

## Out of scope

- `T-MAPPER-DUMPS` for the 17 v2.9.6 families. It stays open until the library
  is reachable.
- DualSystem run-ahead, netplay and TAS (`T-PS-dual-runahead`,
  `T-PS-dual-netplay`).
- The sibling RTL: it is unchanged, so v2.9.2's bitstream pair ships again.
