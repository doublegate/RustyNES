# v2.7.3 "Hearth" — the desktop and web frontends keep what they are given

The fourth release of the ADR 0041 audit line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.7.x-core-frontend-audit-plan.md)). It works from
[`frontend-audit-report.md`](../../docs/audits/frontend-audit-report.md) §2.6-§2.8,
§3.1-§3.7 and §6.2-§6.4, and the
[frontend ledger](../../docs/audits/frontend-disposition.md). Oracle only; the
MiSTer sibling does not change.

## What v2.7.2 closed and did not

v2.7.2 made the core's cartridge memory whole: every bank a board has, and open
bus where it has none. It changed no frontend code. v2.7.1 found that the
**desktop frontend persists no cartridge battery RAM at all** (FE-01): nothing
in `rustynes-frontend` reads `Nes::sram()`, so an in-game save on the desktop
survives only inside a save state. The maintainer placed that here. The mobile
half (AND-09 / MOB-05) stays with v2.7.4.

## The deliverable

Every item is triaged against the report section before it is fixed, and the
verdict goes in the ledger. Every fix that a test can observe is pinned by a
test that fails first; items no test can observe are said to be so, with the
evidence used instead.

## The gate

- Every fixed item's test **fails on `main` and passes after**, with the red
  run recorded, and the fix's mutation (revert it) caught.
- `cargo test --workspace --features test-roms`: 0 failed.
- AccuracyCoin 144/144 and nestest re-run only if the core changes (FE-01 may
  add a core dirty flag; the rest is frontend).
- clippy for every feature combo, including `retroachievements`, `scripting`,
  `scripting,hd-pack`, `full` and both wasm32 invocations; `cargo doc
  -D warnings`; fmt; `no_std`.

## Risks

- **FE-01 overwriting a good save.** A `.sav` must never be written from RAM the
  game has not initialised yet. Load before the first frame, and write only
  after a load attempt, so an unread file is never clobbered by power-on zeros.
- **Audio fixes are hard to test headless.** DESK-04 and DESK-05 touch the host
  audio device. Where no test can drive the device, the fix is kept small and
  the reasoning recorded.
- **Web items have no test harness.** DESK-06 and DESK-07 are verified by the
  wasm build and by reading the code path, and the notes will say so.

## Out of scope for v2.7.3

- Mobile battery saves and every other mobile item (v2.7.4).
- Performance and API hygiene (v2.7.5).
