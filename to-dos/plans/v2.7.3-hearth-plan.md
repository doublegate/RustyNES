# v2.7.3 "Hearth" — the desktop and web frontends keep what they are given

The fourth release of the ADR 0041 audit line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.7.x-core-frontend-audit-plan.md)). It works from
[`frontend-audit-report.md`](../../docs/audits/frontend-audit-report.md) §2.6-§2.8,
§3.1-§3.7 and §6.2-§6.4, and the
[frontend ledger](../../docs/audits/frontend-disposition.md). Oracle only; the
MiSTer sibling does not change.

## What v2.7.2 closed and did not

v2.7.2 made the core's cartridge memory whole: every bank a board has, and open
bus where it has none. It changed no frontend code. v2.7.1 found that the
**desktop frontend persists no cartridge battery RAM at all** (FE-01): nothing
in `rustynes-frontend` reads `Nes::sram()`, so an in-game save on the desktop
survives only inside a save state. The maintainer placed that here. The mobile
half (AND-09 / MOB-05) stays with v2.7.4.

## The deliverable

Every item is triaged against the report section before it is fixed, and the
verdict goes in the ledger. Every fix that a test can observe is pinned by a
test that fails first; items no test can observe are said to be so, with the
evidence used instead.

## The gate

- Every fixed item's test **fails on `main` and passes after**, with the red
  run recorded, and the fix's mutation (revert it) caught.
- `cargo test --workspace --features test-roms`: 0 failed.
- AccuracyCoin 144/144 and nestest re-run only if the core changes (FE-01 may
  add a core dirty flag; the rest is frontend).
- clippy for every feature combo, including `retroachievements`, `scripting`,
  `scripting,hd-pack`, `full` and both wasm32 invocations; `cargo doc
  -D warnings`; fmt; `no_std`.

## Risks

- **FE-01 overwriting a good save.** A `.sav` must never be written from RAM the
  game has not initialised yet. Load before the first frame, and write only
  after a load attempt, so an unread file is never clobbered by power-on zeros.
- **Audio fixes are hard to test headless.** DESK-04 and DESK-05 touch the host
  audio device. Where no test can drive the device, the fix is kept small and
  the reasoning recorded.
- **Web items have no test harness.** DESK-06 and DESK-07 are verified by the
  wasm build and by reading the code path, and the notes will say so.

## Out of scope for v2.7.3

- Mobile battery saves and every other mobile item (v2.7.4).
- Performance and API hygiene (v2.7.5).

## As built

Every item landed. Three audit claims did not hold as written, one bypass
worse than any reported was found, and five items could not be put under
automated test.

| Item | Result |
| --- | --- |
| FE-01 | `battery_save.rs`: `<data_dir>/battery/<rom_sha256>.sav`, gated on a new additive `Nes::has_battery()`. Loaded under the lock that installs the `Nes`; written on change (compared once a second) and at ROM switch, close and exit. No core dirty flag. Never loaded or overwritten when unreadable or the wrong size. Attached at the two real ROM-load sites, deliberately not in `set_nes`, which also re-installs the same `Nes` after an input-binding reload |
| SEC-01 | PNG dimensions checked before any buffer. The report's test idea (a huge header returns `None`) passes on v2.7.2 because of Linux overcommit, so the pinned test decodes a valid 4097 x 4096 PNG |
| SEC-02 / SEC-03 | 64 MiB heap limit; `pcall` / `xpcall` / `coroutine.resume` wrapped to re-raise a tripped budget |
| **FE-02** (new) | A coroutine had **no** instruction budget at all: mlua's per-thread hook removes itself in coroutines. Fixed with `set_global_hook` at both install sites |
| SEC-04 | Unbounded body **refuted** (ureq caps 10 MB; now explicit). SSRF confirmed and fixed per the maintainer's policy: public by default, inward addresses only via `RUSTYNES_COMM_HTTP_ALLOW`, checked in ureq's resolver (DNS rebinding covered); redirects no longer followed, a bypass the report missed. ADR 0016 amended |
| DESK-01 | egui texture uploads before the swapchain acquire, frees after. Not under automated test (needs a GPU) |
| DESK-02 | Four clashes, not the three reported: P2 Select and P3 Right both `L`. Microphone `N`, P3 Select `,`, P2 Select `R`. A serialisation-based test covers every default |
| DESK-03 | At most one `EmuFrame` wakeup pending while fast-forwarding; every frame at normal speed (RA) |
| DESK-04 | Fatal stream errors flag the output; reopened over the same queue every 2 s. Reopen not under test (needs a device) |
| DESK-05 | The audit's case (960 / 1024) **refuted** by simulation: 0 underruns. A real form at a period of at least 2x the target with DRC: 4 in 5 s. Target held at two callbacks or more |
| DESK-06 / 07 / 08 | Responsive canvas (not yet seen on a narrow screen), worklet URL revoked, badges released on ROM change |
| SEC-05 | ffmpeg finalize on a background thread, joined on exit; a new take waits for it. Not under test (needs a window) |
| CON-01 / 03 / 05 | Both web features rejected at compile time; HD-audio source rate bounded to 8-384 kHz; the dead RA `host` field removed |

**Not under automated test**, as the plan's risks predicted: DESK-01, the
DESK-04 reopen, DESK-06, DESK-07 and SEC-05. Each is recorded in the ledger
with how it was verified instead.

**For the maintainer:** power-on movies (`StartPoint::PowerOn`) inherit a
loaded `.sav`, because a power cycle does not clear cartridge RAM. Documented
in `docs/frontend.md`; changing it would change the core's movie semantics.
