# v2.4.1 - v2.5.0 "Fabric" - an independently-written NES core for MiSTer FPGA and SuperStation One, verified against RustyNES

**Status:** APPROVED 2026-08-20. Opens after v2.4.0 "Concordance".
**Decision record:** [ADR 0037](../../docs/adr/0037-mister-fpga-core-independent-hdl-implementation.md).
**Scope, settled:** **v2.5.0 = "the 6502 rung closes"** - the co-simulation harness
plus a cycle-exact 6502, gated on nestest 0-diff and per-cycle bus equality.
**PPU, APU and MiSTer integration are the v2.6-v2.9 programme.**

The reasoning behind every choice below is in ADR 0037. This file is the execution
plan: what lands in which release, and what "done" means for each.

---

## Hard contract

- **The emulation core is untouched.** No behaviour change to
  `rustynes-{cpu,ppu,apu,mappers,core}`; no new hot-path API. AccuracyCoin stays
  **141/141 (RAM decoder)**, nestest 0-diff. `rustynes-cosim` is additive and
  absent from the default build.
- **Provenance firewall, extended to hardware.** `NES_MiSTer` and `fpganes`
  `rtl/` are **strict black boxes**. Instantiating a third-party core as an
  opaque module to compare *outputs* is permitted; reading its source is not.
- **Two repositories.** `crates/rustynes-cosim` here; RTL in a sibling
  `RustyNES_MiSTer` (`rtl/`, `sys/`, `releases/`, plus `tb/nes_top_cosim.sv`,
  which is never listed in `files.qip`).

## Boards

| Board | FPGA | SDRAM |
|---|---|---|
| Terasic DE10-Nano | Cyclone V SE 5CSEBA6 | add-on board **required** |
| Retro Remake SuperStation One | Cyclone V SoC | **128 MB integrated** |

The NES reads cartridge ROM directly and the DE10-Nano's onboard DDR3 is too
slow, so **every** NES core needs the add-on. Order it with the board rather than
discovering it at rung 6. Not urgent: rung 6 is outside v2.5.0 and everything
before it is pure simulation.

## The verification ladder

Strictly ordered. A rung may not start until the one below is green in CI.

### Rung 0 - harness with a null DUT

`crates/rustynes-cosim` (a pure wrapper - **zero `rustynes-core` behaviour
changes**), a `nes_golden_export` CLI, Verilator wired to an empty `nes_top`, and
the three format writers.

**Done =** feed RustyNES's own golden back in *as if it were the DUT* and get **0
divergences** from every diff CLI, plus hash-checkpoint agreement with full
capture over a 100k-cycle window.

Without this, every later red result is ambiguous between "the RTL is wrong" and
"my writer packs a field wrong".

### Rung 1 - 6502 functional

DUT plus a flat 64 KiB testbench memory. Conventions taken verbatim from
`nestest.rs`: PC `$C000`, P bit 5 = 1 / bit 4 = 0, SP `$FD`, cycle counter seeded
to 7. Compare the **7 CPU-only fields** (`pc, a, x, y, p, sp, cyc`);
scanline/dot return at rung 3.

**Done =** at least 8000 instructions, zero differing fields, and nestest's own
result bytes at `$0002`/`$0003` both `$00`.

Worth its cost because RustyNES is already 0-diff against the **Nintendulator**
log, so passing yields `HDL == RustyNES == Nintendulator` - an oracle chain with
an independent third party in it.

### Rung 2 - 6502 cycle-exact bus and interrupts

Rung 1 only checks instruction boundaries, and a 6502 can pass nestest with
entirely wrong dummy reads. Compare `bus_access` / `bus_addr` / `bus_data` /
`put_cycle`, `nmi_line`, and **both IRQ samples** per cycle over a bounded
window, plus a swept interrupt-injection matrix: NMI and IRQ at every
master-clock offset across roughly 20 hazard opcodes (branch page-cross, RMW,
`BRK`, the NMI/BRK hijack, `PLP`/`SEI`/`CLI` delayed-I).

**Done =** 0 per-cycle divergences and 0 divergences in vector-fetch cycle.

*This is where 6502 implementations actually die.*

### Rung 3 - 2C02

Primary surface: **`index_framebuffer` (u16, pre-palette)**, so a palette
difference cannot masquerade as a rendering difference - the failure mode v2.3.8
"Parallax" was built to prevent. Divergences reported through `diff_index_frames`
(popcount / first pixel / bounding box).

**`ppu-state-trace` is diagnostic, never a gate.** Its sprite-evaluation FSM
fields encode *RustyNES's modelling choices*, not hardware facts; gating on them
would force the HDL to transliterate a Rust data structure - bad hardware, and an
odd form of self-derivation given the black-box premise. Partition every trace
field into hardware-observable versus model-internal **before** rung 3 starts.

### Rung 4 - 2A03

Compare the **integer channel levels** from `MixRecord` (pulse / triangle / noise
0-15, DMC 0-127) per CPU cycle - **not** the `f32` mixed output. RustyNES's
non-linear mixer and BLEP resampler are software artifacts with no hardware
counterpart; gating on floats either forces the HDL to reproduce them or produces
permanent unresolvable false failures.

### Rung 5 - NROM plus AccuracyCoin

**Done =** the RAM-decoded status vector is identical **entry for entry** to
RustyNES's, including which tests are `Skipped` and `NotRun`. Stricter than a
pass count, and it catches a DUT that fails one test while accidentally passing
another.

Honest expectation for the first green build: **~90-120 of 141**, with an
open-ended tail.

### Rung 6 - MiSTer integration

Zero accuracy content, all attrition: `sys/` verbatim, `hps_io` ROM download,
video at `CE_PIXEL`, OSD config, Quartus timing closure. Then hardware bring-up
on **SuperStation One first** (integrated SDRAM, no add-on to source), then
DE10-Nano, confirming one `.rbf` boots both.

Sources say the SuperStation One runs MiSTer cores "without modifications", but
none confirms the identical bitstream byte for byte - so this rung **verifies**
rather than inherits, and any divergence is a finding worth publishing.

### Rung 7 - mappers and external memory

NROM at 327 Kb fits entirely on-chip, so **rungs 1-6 need no external memory at
all**. Beyond MMC1, MMC3's 6 Mb forces an SDRAM or HPS-DDR3 controller written
from spec: multi-week, and the programme's second-biggest technical risk.

## Effort, honestly

One competent developer, RTL-comfortable, no prior NES core.

| Rung | Effort | Top risk |
|---|---|---|
| 0 Harness | 1-2 wk | Format-packing mismatch masquerading as an RTL bug |
| 1 6502 functional | 3-6 wk | Undocumented opcodes; decode-ROM BRAM inference |
| 2 6502 cycle-exact | 3-6 wk | Interrupt hijack, RMW dummy writes, DMA cycle stealing |
| 3 2C02 | **8-16 wk** | Sprite-eval per-dot OAM pattern; v/t/x/w at exact dots |
| 4 2A03 | 4-8 wk | DMC DMA stealing back into the CPU; frame-counter IRQ edges |
| 5 AccuracyCoin | 2-4 wk **+ 4-12 wk tail** | Open-ended; may never reach 141/141 |
| 6 MiSTer + hardware | 2-4 wk | Timing closure degrading as the core grows |
| 7 Mappers + memory | 4-8 wk | Writing a memory controller from spec under black-box rules |

**Total 27-54 weeks (7-13 months FTE)** to "NROM plus a few mappers, AccuracyCoin
parity, running on hardware". Against a two-to-four-week window, rungs 2-7 do not
fit and rung 1 fits only if nothing goes wrong. Hence the release table below.

## Explicitly out of scope for v2.5.0

Named so they read as decisions, not omissions.

**Every mapper including NROM rendering** (v2.5.0 closes the CPU rung only) - the
PPU and APU rungs - MiSTer integration and hardware bring-up - FDS, Vs. System,
NSF, expansion audio - savestates, rewind, cheats, RetroAchievements - Zapper,
Powerpad, microphone, Four Score - palette options and video filters -
**contributing the core upstream** (per the cadence rule in `AGENTS.md`, upstream
PRs happen on `vX.Y.0` boundaries where X or Y changed, and there will not be a
core worth offering until well past v2.5.0).

## Risks, ranked, each with a cheap experiment

1. **`sys/` licence versus GPL-3.0-or-later.** If any `Template_MiSTer` `sys/`
   file is GPL-2.0-**only**, the combined bitstream is undistributable and the
   RTL must be GPL-2.0-or-later instead. *Experiment: one hour, **before any
   RTL** - tabulate every licence header in `sys/`.*
2. **Schedule.** Not a risk, an arithmetic fact. Mitigated by rescoping in the
   plan rather than discovering it mid-line.
3. **Black-box discipline collapsing under debugging pressure.** *Experiment: day
   1 - wire a path denylist plus identifier grep into CI, and keep `NES_MiSTer`
   physically outside the workspace, exactly as was done for `ref-proj/`.*
4. **Quartus 17.0.2's SystemVerilog subset**, materially narrower than
   Verilator's. Failure retroactively invalidates every line of RTL.
   *Experiment: one afternoon, week 1 - a ~200-line kitchen-sink module through
   Quartus to a **fitted** netlist, with the resource report as the acceptance
   criterion.*
5. **The core is declined as a duplicate.** Mitigations: the accuracy evidence is
   the deliverable and retains value independently; Retro Remake is a second home
   that still reaches real users.
6. **The oracle is wrong.** *Mitigation: label every rung by whether it has an
   **independent** oracle. nestest (Nintendulator) and the blargg ROMs do; trace
   fields without Mesen2 counterparts do not, and are advisory only.*
7. **Cross-repository golden drift.** *Mitigation: pin the RustyNES commit, encode
   its hash in the golden filename, add a RustyNES-side job that regenerates
   goldens and fails on any change without a schema bump.*
8. **Simulation throughput.** Below ~2 M eval/s a 4200-frame run exceeds an hour
   and the debug loop dies. *Experiment: half a day, before rung 3 - synthetic
   DUT of comparable flop count, measure eval/s.*
9. **No hardware.** Rung 6 is unfalsifiable without a board. *Experiment: order
   one now - longest-lead item, costs less than a developer-day.*

## Verification bar

The standing gate, plus:

- **AccuracyCoin 141/141 (RAM decoder)** and nestest 0-diff for RustyNES itself,
  **verified rather than asserted** on any release touching a chip crate. The
  framebuffer decoder reports 120 and is known-buggy.
- Non-zero test counts confirmed - a filter matching nothing exits 0.
- Every new gate demonstrated to fail by mutation before it is trusted.
- Full clippy matrix: workspace, `debug-hooks`, `full`, `no_std` thumbv7em, and
  **both** wasm32 combinations.
- `crates/rustynes-cosim` absent from the default build.
