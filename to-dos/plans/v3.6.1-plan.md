# v3.6.1: dependencies, the MMC5's window, and region-safe MiSTer save states

A maintenance release after v3.6.0 "Octave" (2026-11-04), planned 2026-11-04
from the maintainer's instruction: one consolidated dependency PR per
repository in place of the open Dependabot PRs, every package at its newest
compatible release, and the five tickets v3.6.0 left for v3.6.1. The
codename is asked at the cut.

## Scope and gates

**Both repositories.**

## The fitter study, scoped down (maintainer, 2026-11-04)

The ticket as written asked for 6 setups (Aggressive Performance, Balanced and
High Performance Effort, each with and without `STANDARD FIT`) x 8 seeds x
both builds = 96 compiles, about 25 minutes each here: some 14 hours even three
at a time. The maintainer chose a staged design of about 40:

- **Stage 1:** the off-die build only (the one that failed at v3.6.0's date),
  all 6 setups at seeds 1-4: 24 compiles, three at a time, in three detached
  worktrees on `origin/main`'s RTL, all at one BUILD_DATE (261105: started
  after midnight so no run crosses one).
- **Stage 2:** the best stage-1 setup and the current one, seeds 1-8, both
  builds: about 16 compiles.

## Results recorded during the release

- **Row 1.** One commit per ecosystem group, `06654d20`: rmcp 3.8, rusqlite
  0.41, toml 1.2, wasm-bindgen 0.2.130 (Trunk's pin with it), the mobile
  bridge's getrandom 0.4; AGP 9.5.0, Gradle 9.8.2, cast-framework 23.0.0;
  wrangler 4.157, vitest 5.1; two GitHub Actions; markdownlint-cli 0.50.0 and
  ruff 0.17.3 (both clean on the corpus). Found on the way: a clippy failure in
  the `script-sqlite` tests no CI job lints. The frontend's two `script-wasm`
  getrandom shims stay on 0.2 / 0.3, which piccolo's tree selects. Dependabot's
  `gradlew.bat` rewrite was CRLF only.
- **Row 2.** `884b1f48`: a 1 GiB decoded budget charged from every declared
  count before decoding, across the main log and every branch.
- **Rows 3-4, found on the way: an ORACLE defect.** The oracle's `fetch_nt`
  meant to pass scanline 0 for the pre-render line and tested `scanline < 0`,
  which never holds (the PPU keeps 261 / 311 there), so line 0's first two
  MMC5 split tiles came from row `($5201 + 261) % 240` on every region. The
  MiSTer core's new NTSC stimulus showed it; the page's v-split counter
  "resets to the vertical scrolling value in $5201 each v-blank". Fixed in the
  oracle; sibling ledger 3.110.
- **Rows 3-4, the epoch: raised to 9 at the cut.** With the window end, the
  every-frame vertical-blank notice and the pre-render split row together,
  `cargo test --workspace --features test-roms,commercial-roms` passes 4,048 /
  0 / 20 (v3.6.0: 4,030 / 0 / 20), the 1,116-dump boot coverage and the
  commercial snapshots included, *Uchuu Keibitai SDF* (the one commercial
  split game) among them: no committed frame, sample or golden moved, which is
  the epoch's trigger. A game that reads CHR through `$2007` on line 240, or
  splits the first two columns with `$5201` set, now behaves differently; none
  is in the corpus. The fix commit (`875e824b`) said the epoch stays 8; the cut
  raises it to 9 instead, by v3.5.1's precedent (the maintainer raised epoch 7
  for the same shape of change: no recorded output moved, a bus value did), and
  the release rule's own words ("anything that alters a frame"). The
  fingerprint table's rows did not move; only its epoch line was re-blessed.
- **Row 3's suppressed-VBL half has no DUT stimulus** (none lands a `$2002`
  read on the race dot): covered by the oracle's PPU unit test only; recorded
  in the sibling's ledger 3.109 and its mutation table.
