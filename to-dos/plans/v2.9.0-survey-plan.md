# v2.9.0 "Survey" — every audit re-checked, and the SuperStation One surveyed

The first release of the v2.9.x line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.9.x-final-audit-and-hardware-plan.md)). The v2.8.x line closed
every ledger row it targeted; this release checks that claim against the tree
as it now stands, surveys the target console, and records the decisions the
line plan reserved for v2.9.0. It also ties up the small loose ends left by
v2.8.3 and v2.8.4 (maintainer instruction).

## What v2.8.4 closed and did not

v2.8.4 "Tether" closed the v2.8.x line: every RTL ledger row has a
disposition, three PARTIAL (R-3.1a, R-3.1b, R-4.1). It left the SDRAM clock
phase to the board (v2.9.2), and three cosmetic review notes, a skip-counting
gap in the co-simulation ladder, and an untested CI feature as loose ends.

## Decisions recorded (maintainer, 2026-09-26)

| Question | Decision | Consequence |
| --- | --- | --- |
| Does v3.0.0 remove the v2.7.5 deprecations? | **Yes, all of them, and the dead NMI edge detector with them** | The 19 items (18 `rustynes_cpu::Bus` methods, `ApuBus`) and `sample_nmi_edge` with its two fields go at v3.0.0. The fields are in the `.rns` BUS section, so this is a save-state format change, which ADR 0041 said was not planned: recorded in ADR 0042, and v3.0.0 must decide how older `.rns` files load |
| How is the re-audit done? | **Claude subagents, one per scope** | The original instrument (`agy`) left no recorded prompts, so no option reproduced it. Each agent re-verifies every ledger row and then looks for new defects |
| Power-on movies and a loaded `.sav` | **Power-on movies start from cleared battery RAM** | TASVideos' convention. Recording and playing a `StartPoint::PowerOn` movie clears cartridge battery RAM first; the `.sav` file itself is never touched |
| Off-die bitstream, SDRAM size "unknown" | **The core probes the SDRAM itself** | The framework reports "unknown" when the menu core has not run since power-on (a `bootcore=` autoboot), and the off-die build held reset forever in that case. The SS1's SDRAM is an onboard 128 MB BGA, always fitted; the same `.rbf` targets the DE10-Nano, where it is a module. An RTL change with a co-simulation gate and a timing close |
| The v2.7.4 mobile device checklist | **Moves to its own release, v2.9.3** | Board follow-ups become v2.9.4+ |

## The deliverable

1. **The re-audit.** Four scopes (core, frontend, libretro, RTL), each ledger
   row re-proven against the current tree (HOLDS / REGRESSED / CHANGED), then
   new findings triaged the same way as the originals: evidence, red first,
   fix, gate. Results go into the four ledgers as a v2.9.0 section.
2. **The SuperStation One audit.** Research against the framework
   (`Main_MiSTer`, `Menu_MiSTer`, the vendored `sys/`) and the SS1's published
   documentation, and fixes for what this machine can verify. The headline
   finding: the SS1's `yc.txt` has no entry for this core, and the NES core's
   entry is wrong for it -- `NES_60.1` encodes a video clock of 12x the colour
   subcarrier, and this core's `CLK_VIDEO` (`clk_sys`, 21.477272 MHz) is 6x,
   so its entry is `RustyNES_60.1=183251937963` (2^40 / 6).
3. **`sys/` against `Template_MiSTer` HEAD.** Done: upstream HEAD is the pinned
   `3ea1134c`, nothing to re-vendor.
4. **Power-on movies from clean SRAM.**
5. **The off-die SDRAM presence probe.**
6. **Loose ends**: the ladder counts what it skipped; `check_reset_wiring.py`'s
   sink count; the three notes deferred from #37; `av-record` tests in CI; the
   stale v2.8.4 branch; the MARM compaction request.

## The gate

- Every re-audit ledger row reported with evidence, and every new finding
  either fixed (red first, the fix's mutant caught) or dispositioned.
- The emulator stays byte-identical except where a finding requires otherwise
  and says so: AccuracyCoin 144/144 and nestest 0-diff re-run on any core
  change; the full `--features test-roms` suite.
- The movie change pinned by a test that fails on the old behaviour.
- The SDRAM probe: a co-simulation gate that fails without it (a size-unknown
  boot held in reset) and passes with it, a gate for "no SDRAM fitted", and
  the full ladder on-die and off-die from a frozen worktree. A Quartus compile
  at seed 5 that closes timing for both builds.
- Release audits and the pre-release gate.

## Risks

- **The probe is RTL on the reset path.** It must not delay the on-die
  build's reset, and it must not declare SDRAM present on a board without it.
- **The movie change alters playback of movies recorded with a `.sav`
  loaded.** That is the point; the CHANGELOG says so.

## Out of scope

- Removing the deprecations and the NMI detector: decided here, done at v3.0.0.
- Anything that needs the board: the SS1 FPGA part and SDRAM part number, the
  SDRAM clock phase, the video-path measurements (v2.9.2). **No hardware has run
  any bitstream.**
- The mobile device checklist (v2.9.3).
