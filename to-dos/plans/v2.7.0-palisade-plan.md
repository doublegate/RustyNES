# v2.7.0 "Palisade" — untrusted input stops at the boundary

The first release of the ADR 0041 audit line
([ADR 0041](../../docs/adr/0041-hardware-release-is-v3.0.0.md);
[line plan](v2.7.x-core-frontend-audit-plan.md)). It works from
[`core-audit-report.md`](../../docs/audits/core-audit-report.md) §2 and the
[core ledger](../../docs/audits/core-disposition.md). Oracle only; the MiSTer
sibling does not change.

A save-state file is untrusted input: a user can hand-edit one, corrupt one, or
load one another program wrote. Today a hostile `.rns` can make the emulator
panic, and on a release build (`panic = "abort"`) that kills the process. This
release makes every such input fail at the boundary with a typed error. It also
fixes the audio defect the audit calibration turned up.

## What v2.6.23 closed and did not

v2.6.23 changed no emulation code. The audits it committed located, among other
things, three save-state crash classes (IMP-01, IMP-02, IMP-03) and a fuzz target
that exists but cannot find them. The calibration also found T-01, a pulse-1
sweep defect that is not in any audit.

## The deliverable

| Item | Source | What changes |
| --- | --- | --- |
| **T-01** | calibration | `rustynes-apu` pulse sweep: a negative negated target clamps to zero (NESdev "APU Sweep") instead of wrapping to `$FFFF`. Pulse 1 stops muting on the `$4001 = $08` idiom, the documented way to disable the sweep |
| **IMP-01** | core audit §2.2 | PPU snapshot rejects `spr_count > 8` |
| **IMP-02** | core audit §2.3–2.4 | APU snapshot rejects out-of-range duty, step, triangle step, envelope `volume_or_period` / `divider` / `decay`, sweep `shift` / `period`, DMC `dac` / `rate_index` / `bits_remaining`; BlipBuf rejects a zero sample rate, a non-finite or non-positive CPU rate, a phase outside `[0, 1)`, a non-finite held value, and a rate RATIO above one output per CPU cycle, since a finite but huge ratio hangs exactly like an infinite one |
| **IMP-03** | core audit §2.5 | `SectionIter` uses `checked_add` for `body_start + len` (a real overflow only where `usize` is 32 bits: `wasm32`, `thumbv7em`) |
| **Fuzz** | core audit §2 | The existing `fuzz/fuzz_targets/save_state.rs` is made able to find these: seeded from a real snapshot, and it RUNS the machine after a successful restore, because every IMP-01/02 panic fires on the next tick, not during the restore |
| **§2.1** | core audit | `#![forbid(unsafe_code)]` on the five chip crates |

## The gate

- **T-01:** `pulse1_negate_shift0_clamps_to_zero_and_does_not_mute` fails on
  v2.6.23 (**measured: red**) and passes after the fix. A companion test sweeps
  every shift 1–7 and every period 8–`$7FF` and shows the clamp changes nothing
  else. Every golden the fix moves is listed with the reason it moved; none is
  re-cut blind.
- **IMP-01/02/03:** one test per bound, each feeding a real snapshot with a single
  field corrupted and asserting a typed `Err`. Each check is mutated out and its
  test must go red.
- **Fuzz:** the improved target run against the tree BEFORE the validation lands
  must produce a crash (evidence that it reaches the defect). After the
  validation, `-runs=2000000` or more with zero crashes. Both results are
  recorded, with the run command and seed count.
- **forbid(unsafe_code):** builds, including the `thumbv7em` `no_std` target.
- **No regressions:** AccuracyCoin 144/144 and nestest 0-diff re-run, not
  assumed; the full `--features test-roms` workspace suite; every CI clippy
  combination; rustdoc with `-D warnings`.

## Risks

- **T-01 changes audio.** Any audio golden that exercises the idiom moves. That
  is the fix working, but each moved golden gets checked individually before
  being accepted.
- **Stricter restore could reject a real save.** Every bound is the hardware
  register's own width, and states the emulator itself writes stay inside those
  widths, so the round-trip tests are the guard.
