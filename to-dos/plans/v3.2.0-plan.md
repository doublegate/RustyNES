## Scope decisions (2026-10-08, at the start of the release)

- **157 (Datach) is in scope**, with a barcode-reader input device (maintainer).
- **FFE 6 and 17 are added to item 1.** A recursive index of the library
  (24,763 dumps read by header) found none of the 15 listed families
  implemented, at least one dump for each, and also that FFE 6 (153 dumps) and
  17 (51) are not implemented either, against 8's two. The three are the same
  copier hardware on the same wiki pages, so they are done together.
- **The "two staged *Doraemon* hacks refused as mapper 8" exist** (corrected
  the same day). An earlier note here said they did not: a search by directory
  name and header could not find them, because they sit in
  `mapper-072-Jaleco72/` and read as mapper 8 only after the dirty-tail
  ("DiskDude!") masking rule. `external_coverage.rs` lists both in
  `UNSUPPORTED` for exactly that reason. The gate stands as written, plus the
  library's own mapper-8 dump (*Dragon Ball - Shen Long no Nazo (J) [hFFE]*).
- **"No recorded boot" means "no staged dump".** `external_coverage.rs`
  discovers and snapshots every staged dump, so item 4's gap is the supported
  families with a library dump and nothing staged: 154, 243, 268 and 290
  (measured against `mapper_tier` itself, 191 supported). All four are also in
  item 3, which absorbs them.

## Findings during the build

- **Mapper 290 never booted.** Its 32 KiB PRG mode -- the power-on mode -- read
  `$C000-$FFFF` through the 16 KiB window, so the reset vector came from the
  wrong half and *Asder 20-in-1* showed a uniform grey frame. Fixed red-first
  (`m290_prg_modes_follow_the_size_bit`); it changes output against v3.1.0, so
  `EMULATION_EPOCH` is 4. 290 stays BestEffort: the new capture shows a top band
  of scrambled tiles nobody has compared with hardware.
- **GoodNES's mapper-243 Sachen titles are mapper 150.** NESdev lists
  *Strategist*, *Poker III 5-in-1*, *Chinese Checkers*, *Magic Cube* and others
  as SA-015 (150); 243 is *Honey Peach* alone. The vendored game database also
  routes them to 243. Those staged under 243 were removed again; 243's evidence
  is *Honey Peach*. **Open:** *Poker III* renders garbled under both decodes,
  and the database rows for the SA-015 titles disagree with NESdev. Neither is
  fixed in v3.2.0 so far; both are recorded in `docs/compatibility.md`.
- **Mapper 47's second game is reachable.** A new `InputScript::Presses`
  (arbitrary single-frame presses) drives DOWN then START on the cart's game
  select, which reaches *Nintendo World Cup* through the block register; a
  mutant that ignores the block bit fails `extended_m47_nintendo_world_cup_block_1`.
- **Ten "blank" dumps need Famicom wiring, not a fix.** *Sansuu 1/2/3* (185),
  *Bio Hazard*, *Xiao Au Jiang Wu* (015), *Final Combat* (139), *Xi You Ji Hou
  Zhuan* (162), *Digital Dragon* (164), and both 227 dumps write the PPU
  registers inside the front-loading NES's power-on warm-up, where they are
  ignored; with `ConsoleModel::Famicom` all ten draw their titles. The coverage
  sweep now boots them as a Famicom (`FAMICOM_WIRED`), with a ratchet that
  each must still be blank on the NES model; a mutant that drops the model
  fails all ten. *Subor V1.0* was not one of them -- the ratchet refused it,
  since it draws on the NES too -- it blanks its own menu at about f375, so it
  gets a 350-frame capture. KNOWN_BLANK: 52 -> 41. **Maintainer decision,
  recorded not taken:** the frontend does not pick the Famicom model from the
  ROM (`ConsoleModel`'s stated design); a player has to choose it in Settings.
  Auto-selecting it per game would be a default-behaviour change.
- **The last two triaged blanks have causes, not fixes.** *Gradius II (VC)* is
  mis-headered: the payload is the VRC4 cartridge's (four bytes differ, the
  Virtual Console edit) under a mapper-9 Vs. header, and it draws when given
  the cartridge's mapper-25 header. *Chu Liu Xiang* is open: routed to 176/2
  like its two working siblings, it runs the FS005 copy-protection stub
  correctly, then crashes into data at `$FF40` in frame 4; no 176 submapper
  or other Waixing mapper boots it, so a bad dump is the leading explanation.
  Both stay in KNOWN_BLANK with the cause at the entry. Item 2 is done.
- **Item 5's "region placeholder off" needs no change.** The core's OSD has
  no region item (`rtl/emu.sv` on `feat/v3.2.0`: the options are the
  palette, the custom `.pal` load and, from this release, the sprite limit),
  and PAL timing is not implemented (`emu.sv`'s own comment at the video
  mode). A region entry appears when PAL does (v3.6.0, F4), not before.
- **VRC4's IRQ mode bit was inverted (misc branch, `7a437805`).** Mappers
  21, 23 and 25 read `$x00x` control bit 2 as "1 = scanline"; VRC_IRQ says
  "1 = cycle mode, 0 = scanline mode", as VRC6 and VRC7 already had it.
  Checked against the vendored page. It moves commercial frames (nine of 17
  staged VRC2/4 dumps, every difference inspected a repair), which v3.2.0's
  epoch 4 covers.
- **The 24C02 fix generalised.** The Datach found the EEPROM model cleared
  the 24C02's word address on START; it is the chip's behaviour, so mapper
  16 has it too (`ba20c328`). No mapper-16 baseline moved.

## Risks

- Several families above are Japan-only or pirate boards, and demand for them
  is unverified. The Dropbox search comes first, and a family with no dump and
  no notable title can move to v3.8.0's long tail.
- On-die M10K is at 85%. Families that need memory are off-die only from the
  start.
