# v2.9.4 "Plumb" — the records made true, and CI made to run what it only lints

The first release of the line to v3.0.0
([line plan](v2.9.4-to-v3.0.0-line-plan.md),
[ADR 0043](../../docs/adr/0043-v3-is-the-api-major-and-a-release-candidate-core.md)).
It changes no emulation behaviour. It does three things: puts the v3.0.0
decision on paper, brings the records in both repositories back in line with
the code, and closes the CI gaps that let tested-looking code go unrun.
("Plumb" is a provisional codename; the maintainer may rename it before the
cut.)

## What v2.9.3 left

- **The v3.0.0 question**, open in ADR 0041's amendment. Decided on
  2026-09-29; ADR 0043 and the line plan are the first commit on this branch.
- **Records that contradict the code**, found by the 2026-09-29 surveys:
  - `docs/STATUS.md`'s mapper section says 172/26 against the classifier's
    174/28 (`crates/rustynes-mappers/src/tier.rs`);
  - `docs/frontend.md` still says "139/141";
  - the store-deferral text in `docs/android.md` and `docs/ios.md` names retired
    targets;
  - `to-dos/DEFERRED-AND-CARRYOVER-FEATURES.md` still has about 37 open boxes,
    many already shipped;
  - the sibling's `HARDWARE_TESTING.md` §7 and `submission-case.md` are stale;
  - the board kit's `EXPECTED.md` names an off-die md5 that matches no shipped
    file.
- **CI that lints without running:**
  - five frontend features and the `debug-hooks`/`hd-pack` paths in the chip
    crates are only clippy-checked;
  - eight fuzz targets exist and no workflow builds them;
  - there is no coverage measurement;
  - nothing watches for toolchain drift while the pin is 1.96.

## The deliverable

1. **ADR 0043 and the line plan** (done: `a42e85c8`), with the MiSTer
   checklist's deadline sentence and its audit moved together.
2. **Records.** Every current-state claim is re-checked against the code and
   corrected: STATUS (mapper tiers, test counts, AccuracyCoin), frontend.md,
   the android and ios store sections, both ROADMAPs, the DEFERRED catalogue,
   the CHANGELOG-FULL scope note, and stale code comments (`movie_ui.rs:23`,
   sibling `emu.sv:549`). The GitHub wiki is refreshed to v2.9.4.
3. **Sibling records.**
   - `HARDWARE_TESTING.md` §7 and its checklist.
   - `submission-case.md` gate counts and its off-die framing.
   - The `rung7-mappers.md` status line and its stale MMC3 section.
   - `rung6-integration.md` MENUMASK notes, and the retrospective audit's Open
     entry.
   - The board kit re-staged against the released v2.9.3 pair.
   - The five agy nits from sibling #33 and #37.
4. **CI coverage**, each new step shown able to fail:
   - run the tests behind non-default features:
     - frontend `full`, which subsumes the `av-record` step;
     - `debug-hooks`/`hd-pack` in the chip crates and the harness;
     - `script-ipc`/`script-sqlite` in `rustynes-script`.
   - a fuzz job that builds all 8 targets and runs each for a bounded time;
   - `cargo llvm-cov` with a recorded baseline and a floor below it;
   - a non-blocking stable/beta canary job;
   - `rustynes-cheevos` inheriting the workspace lints.

## The gate

| Item | Measured by |
| --- | --- |
| Records | `git grep` for each stale value finds only history. Every DEFERRED box ticked cites a file, and every one left open says why |
| Feature-gated tests | Each new step's test count is measured locally and quoted here. Its CI job is `success` in the PR run, with a non-zero count |
| Fuzz | All 8 targets build in CI and each runs its time box. A deliberately broken target turns the job red |
| Coverage | The baseline line-coverage percentage is recorded in `docs/testing-strategy.md`; `--fail-under-lines` sits a stated margin below it and fails when lowered past the measurement |
| Canary | Runs on schedule and dispatch, `continue-on-error`, and never blocks `CI success` |
| cheevos lints | `[lints] workspace = true` compiles clean under `clippy -D warnings` and `missing_docs` |
| Board kit | `EXPECTED.md` md5s equal the v2.9.3 release assets (`c17b0f37...`, `75ae3a99...`) |
| Standing | fmt, clippy (every feature set, both wasm builds), rustdoc, no_std, `--features test-roms`, the six release audits; the sibling's `make -C tb all` and lint |

## Out of scope

- Any emulation change: that is v2.9.5 onward.
- Hardware work.
- The sibling ladder re-run, since no RTL changes. The board kit is re-staged,
  not re-tested.
