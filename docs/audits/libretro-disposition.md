| L-1.1 | Panics unwind across `extern "C"`; `.expect` on the run path; no `catch_unwind` (§1.1, Fix 9) | FIXED | Two halves; the unwind build costs ~0.1% of retired instructions per frame (`docs/performance.md` §v2.8.0). The shipped core aborted on panic (`[profile.release] panic = "abort"`, built `--release` on every path), so `catch_unwind` would have been dead code: the libretro builds now set `CARGO_PROFILE_RELEASE_PANIC=unwind` (crate `Makefile`, `.gitlab-ci.yml` `.core-defs`, the `libretro-cross` gate). A direct `cargo build --release` bypasses all three (and the crate is the workspace's only `default-members` entry), so `build.rs` warns when the override is absent and `on_load_game` logs `cfg!(panic = "abort")` to the frontend: verified by building both ways, the log string is in the aborting `.so` and absent from the unwinding one (Copilot, #556). Then `RustyNesLibretro::contained` wraps every emulation callback (run, serialize, unserialize, reset, load, the disk and cheat mutators) in `catch_unwind`; a caught panic POISONS the core (later calls inert) and keeps the console allocated, because the frontend holds pointers into its memory: the audit's Fix 9 (`self.nes = None`) would have been the use-after-free of L-1.3. The seven `.expect`s are `let-else` returns. Test `abi_tests::a_panic_inside_a_frame_is_contained_and_the_memory_stays_valid`. Mutations: without `catch_unwind` the test binary dies (`non-unwinding panic`, SIGABRT), exactly the frontend's fate; without poisoning, and with the audit's drop-on-panic, the test fails. The `panic!` sites inside `rust-libretro` itself are "core not initialized" guards (and two null-callback checks); they fire only if a frontend calls in before `retro_get_system_info` creates the instance. That RetroArch does not is inferred from the core running in it, not traced through RetroArch's source. **Maintainer decisions (2026-09-25, review on #556):** (1) a direct `cargo build --release` of the core stays a build-time WARNING (plus the load-time log), not an error, because the documented `cargo build --release --workspace` builds this crate too; (2) a poisoned core keeps its memory readable and RetroArch still writes battery RAM after a contained panic -- a panic cannot tear a byte, so what is written is the cartridge's RAM at one instant, as after a power cut, and withholding it would lose every save since the load | v2.8.0 | #556 |
